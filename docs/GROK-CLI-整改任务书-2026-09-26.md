## 3. P0：配置与数据可靠性

### R01 列表测试保存旧配置快照

**状态：已确认代码风险，优先复现。**

位置：`apps/PopGlot.Windows/Sections/ServicesSection.xaml.cs`，`TestProfile_Click`；`Services/ProfileManager.cs`，`Load/SaveAsync`。

当前路径：请求前 Load 整份 config → await 测试 → 给旧 profile 写 LastTest 字段 → SaveAsync 整份 config。编辑器测试的代次保护没有覆盖这条列表路径。期间修改其他配置、删除引擎、切换当前引擎，旧快照有覆盖新值或复活已删项的风险。单纯给 Load 和 Save 分别加锁不足以保护跨 await 的读改写。

修改要求：测试开始锁定引擎 ID、连接配置和凭据版本；完成后通过原子更新接口读取最新配置，仅在目标仍存在且版本匹配时更新验证字段。不同引擎测试可独立进行，同一引擎不允许重复发送。不要把整份旧配置写回。编辑器验证持久化也复查同样的读改写竞争。

验收：用延迟假执行器覆盖测试期间改模型/地址/Key、改其他引擎、切默认、删除目标、两个引擎乱序完成；成功和失败都不能覆盖新配置；删除目标不得复活；不访问真实密钥。

### R02 导出会覆盖同分钟文件

**状态：已确认。**

位置：`Sections/LibrarySection.xaml.cs`，`ExportHistory/ExportVocabulary`。

文件名使用 `yyyyMMdd_HHmm`，随后 WriteAllTextAsync，重复导出可覆盖现有文件。

修改要求：使用不覆盖的文件创建方式，冲突自动附加序号或唯一后缀；秒级时间本身仍不能保证无冲突。失败不能留下被报告为成功的半文件。反馈提供“打开文件/所在文件夹”的明确入口，避免常驻长路径；保留 CSV/Anki 公式注入防护。

验收：同一时刻并发两次导出，原文件字节不变，两份文件存在；只读目录、磁盘写入失败给出可操作短提示。

### R03 清空与删除的恢复体验不一致

**状态：已确认交互差异；可撤销机制为产品改进。**

位置：`LibrarySection.xaml.cs`，`RequestDeleteRow/ClearCurrent`；HistoryStore、VocabularyStore；`Sections/DataSection.xaml.cs`。

单条删除需要限时第二次点击，清空全部却直接执行。用户已明确反对隐蔽二次点击和“点击无反应”，不能恢复该体验。

修改要求：统一为立即反馈的删除/清空流程，优先提供短期“撤销”；撤销必须只恢复本次删除的条目，不覆盖此后新增或修改的数据。若采用短期备份，规定存放位置、权限、保留期限和清理规则；未完成恢复机制前不得宣称删除可撤销。

验收：删除/清空后新增条目再撤销；切换历史/生词后撤销；文件写入失败、损坏只读状态、重启边界；单击行为明确，不能要求用户猜第二次点击。

### R08 图标与信息显隐

**状态：产品改进。**

名称、Tooltip、AutomationProperties.Name 一致；悬停/键盘焦点可发现功能。常态显示最少必要信息，失败解释按需出现；加载不抖动，切换不残留旧提示。用户所说“文字隐藏切换仍显示很多字”的具体控件尚未唯一定位，必须走查工作台/浮窗阅读切换与常态提示，禁止猜测后随意删掉正文。
