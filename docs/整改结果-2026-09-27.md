## 三、重点整改项详细说明

### 1. P1 译文段落与自动排版全链路保真

- **问题根因**：
  1. **提示词层**：底层非流式与流式 Prompt 缺少针对段落、有意义换行、对话和表格的显式保真约束，易诱导模型将多段译文合成一段大文本输出。
  2. **渲染展示层**：原 `MarkdownPresenter.RenderToFlowDocument` 针对没有空行分隔的相邻行无条件使用空格拼接合并为一个段落；且不支持表格、块引用、嵌套列表缩进及规范硬换行。
- **整改措施**：
  1. **核心 Rust Prompt 重构**：在 `crates/popglot-core/src/provider.rs` 的非流式与流式系统提示词中注入严格排版准则：
     > “保留原文的标题、段落、列表、有意义换行、对话和表格结构，不要把多段内容合并为一段。对于明显由 OCR 或页面宽度造成的截断断行，仅在同一语义段落内自然合并；必要时按语义整理自然段，使译文清晰易读。不要新增原文没有的内容，不要总结或省略，不要输出排版说明。代码、命令、链接、数字及占位符保持原样。”
  2. **WPF MarkdownPresenter 引擎全面升级**：
     - **智能段内重排门禁（`ShouldReflowAdjacentProse`）**：精准拦截对话说话人（如 `Alice:` / `张三：`）、邮件称呼/署名（如 `尊敬的客户`、`此致敬礼`、`技术支持团队`）、句末终结标点（`。！？；：.!?;:`）、中文短诗句（<= 10 字以逗号结尾）、列表行等，防止误并。仅对段内纯文本截断（如 OCR 扫描断句）进行段内流式合并。
     - **Markdown GFM 表格**：完整解析 `| 表头 |` 与 `:--- | ---:` 分隔行，动态构造带有 `SurfaceMutedBrush` 表头、精确列对齐与单元格边框的 FlowDocument `Table` 组件。
     - **Markdown 块引用（Blockquote）**：解析 `>`，生成带左侧 3 DIP `AccentBrush` 边框、独立缩进与斜体样式的 `Paragraph`。
     - **超链接安全白名单（R10）**：解析 `[text](url)`，严格仅放行 `http://` 和 `https://` 协议，杜绝本地命令注入与特权 URI 触发。
     - **多层嵌套列表**：根据前导空格/制表符自适应缩进（`16 + nestLevel * 16` DIP）。
     - **CommonMark 硬换行**：行尾双空格或反斜杠精确解析为 `new LineBreak()`。
     - **纯文本导出（`ToPlainText`）**：自动还原块引用内容并将超链接展开为标准格式，保证剪贴板复制、文件导出与屏幕渲染完全一致。
- **9 类典型场景验收测试结果**：
  在 `tests/PopGlot.Windows.LogicTests/Program.cs` 编写 `MarkdownPresenterNineAcceptanceFixturesConform`，9 大测试场景全部通过：
  1. 三段邮件带署名：正文段落与署名各自独立，未发生粘连；
  2. 对话与诗行：`Alice:` 与 `Bob:` 独立分段，诗歌《登鹳雀楼》4 行均保留换行；
  3. 标题与编号步骤：标题、引导语及 3 项步骤严格产生 5 个独立块；
  4. OCR 截断与空行：空行内被断开的句子正确重排合并，跨空行的两个段落各自独立；
  5. 连续句子：以句号结尾的连续长句维持语义分段，无粘连无删减；
  6. 代码围栏：代码块语法高亮背景、复制按钮与缩进字节完全保真；
  7. 表格与链接：表格与超链接均正确生成对应 WPF 控件元素；
  8. 短词与单句：单个单词不会产生多余段落或前言总结；
  9. 全生命周期一致性：纯文本提取与渲染后结构一致。

### 2. UI 与产品体验全面整改

1. **控件视觉标准统一**：
   - 表单基线高度统一为 36 DIP，修复可编辑下拉框内部继承的额外 `ContentPadding`，使输入文字与占位符（Placeholder）横向起点绝对一致；
   - 彻底解决中文输入法（IME）由于高度压迫导致的选词候选框或文字上下裁切问题。
2. **视觉套框与留白降噪**：
   - 移除引擎编辑页与表达方式页中的重复嵌套外边框与多余背景底色，保持清晰的标题分组间距；
   - 表达方式设置页精简冗余长文本说明，管理入口统一精简为「管理」；切换提示精炼为「下次翻译生效」；
   - 模型目录刷新状态精简为「模型目录已更新 · N 个」，杜绝未经验证的「模型可用」误导文案。
3. **矢量化与无障碍改进**：
   - 将工作台与主窗口中的文字符号对勾 `"✓"` 替换为标准矢量路径 `IconCheck` (`AccentBrush`)，彻底解决不同系统字体库缺失导致的对勾变形或乱码；
   - 规则删除按钮 ToolTip 由 `"点击两次确认"` 纠正为 `"删除规则"`，读屏名称同步更新。
4. **API Key 四状态机落地**：
   - 界面状态精确区分为：**未填写**（显示占位符「本地引擎可留空」或「请输入 API Key」）、**已保存**（显示掩码 `••••••••••••  已保存`）、**正在替换**（用户正在输入新密钥）、**已清除**（用户显式清空密钥）；
   - 清除按钮 ToolTip 与 `AutomationProperties.Name` 随状态动态调整，操作具有确定性预期。
5. **响应式断点与极端尺寸表现**：
   - 窄窗断点（< 560 DIP）时，主工作台原文/译文由双栏左右排列自动平滑切至上下纵向堆叠，导航栏自适应收拢为图标栏；
   - 标题栏与右上角窗口控制按钮、搜索框与快捷键徽章在窄窗下留有安全间距，无文字挤压重叠；
   - 离线帮助窗口边框内边距合理，内容与边框不粘连。
6. **双主题与多 DPI 离屏验证**：
   - 在暗黑（Dark）与浅色（Light）两种主题下，所有文本对比度均符合 WCAG AA 标准，状态颜色（成功绿、警告黄、错误红）语义一致；
   - 完整验证 100%、125%、150%、200% 四种系统缩放倍率，亚像素抗锯齿与 DWM 阴影正常，无文字发虚与边框撕裂。
7. **文字隐藏/收起切换路径走查与归因**：
   - 走查工作台（`TranslateSection`）与浮窗（`TranslationPanelWindow`）的全部显隐逻辑：
     - 原先表达方式设置页在切换翻译语气（准确/自然/正式）时常驻展开数十行长文说明，并伴随一个只读的“要点”静态解释区块，导致用户切换隐藏/选项时界面仍被大段文字充斥；现已彻底移除常驻大段说明与多余要点区块，仅在选项 ToolTip 悬停时按需展示。
     - 浮窗折叠/展开与取消操作（`TranslationPanelWindow.xaml.cs`）的清理链路：当会话无内容（清空或取消无 Partial 结果）时，强制将 `TranslationTextBox`、`TranslationRichBox`、`ExplanationBox`、`TermsList` 设为 `Visibility.Collapsed`，杜绝旧会话残留的大段解析文字或骨架屏在窗口收起时仍突兀展示。
8. **弹出菜单阴影直角消除、紧凑宽度、状态呼吸灯与连接测试卡片美化**：
   - **消除菜单直角黑边与方框色差（“后面怎么有正方形/外面有一层别的颜色感觉”）**：WPF 原生 ContextMenu 根元素为带阴影的 Border 时，由于 HWND 窗口尺寸正好等于 Border 尺寸，外散的 DropShadowEffect 会在窗口矩形边缘被生硬截断，导致四角产生直角方块并在浅色主题下显露暗色方框。修复为在 `Themes/Controls.xaml` 的 ContextMenu 模板中设置 `HasDropShadow="False"`，外包 `<Grid Margin="10,4,10,12" Background="Transparent">`，给阴影预留充分衰减透明边距；配合 `HorizontalOffset = -10; VerticalOffset = -2;` 实现弹出框与锚点按钮无缝吸附。
   - **紧凑菜单尺寸（“同时选择还是太宽”）**：样式默认 `MinWidth` 降为 100 DIP；`TranslationStyleMenu.Build` 显式限定 `MinWidth = 100; MaxWidth = 135;`，两字选项（准确/自然/正式/管理）紧凑贴合，不再遮挡工作台相邻按钮。
   - **极简状态与呼吸灯动效（“切换模型文字描述太多直接写名称或加入呼吸灯”）**：
     - 底部状态栏按钮始终精炼展示引擎名称（如 `内置免费引擎` 或自定义服务名），剥离繁琐的毫秒延迟与状态字眼；
     - `MainWindow.xaml` 为 `EngineDot` 加入 `Storyboard` 动态渐变（`DoubleAnimation` 不透明度 1.0~0.3 循环），在探测过程中触发 `Tag="Testing"` 呈现真实呼吸灯动效，探测完成后常亮（绿灯可用/黄灯告警/灰灯未测）；
     - 延迟与错误详情完整保留在 ToolTip 悬停提示中。
   - **引擎测试与状态卡片美化（“测试变漂亮一些，像开关那样完整修复”）**：
     - 将 `ServicesSection.xaml` 中「测试连接」按钮的图标由打勾（`IconCheck`）统一为烧瓶试管测试图标（`IconTest`）；
     - 将 `TestStatusPanel` 重构为带圆角与自适应底色的胶囊卡片（Border `CornerRadius="6"`, `Padding="10,8"`），成功、失败、告警时动态套用柔和状态色（`SuccessSoftBrush`、`DangerSoftBrush`、`WarningSoftBrush`）与半粗体摘要排版，视觉如同现代系统设置项一般精致利落。

## 六、最新针对性整改修复记录（要点排版与引擎切换）

根据用户深度测试反馈，重点整改并解决了以下四项关键体验与功能问题：

1. **要点（Summary）Markdown 排版渲染（`TranslateSection` 与 `TranslationPanelWindow`）**：
   - **问题现象**：模型返回的要点总结包含列表项（`•`）与加粗语法（`**xxx**`）等 Markdown 语法，但在工作台与浮窗界面均作为纯文本展示在 `TextBox` 中，排版生硬且未格式化。
   - **根本原因**：`PaintSummary` 与 `PaintPanelSummary` 原先直接将 `TranslateRichResult` / `TranslationRichBox` 设为 `Collapsed`，直接将原始内容填入纯文本框。
   - **修复措施**：调用 `MarkdownPresenter.RenderToFlowDocument` 将 Markdown 格式化解析并渲染至 `RichTextBox` 流文档视图中，支持列表项、加粗标记与换行层级，失败或空文本时优雅降级至常规文本框。

2. **本地 Gateway 与自建端点（无 Key）切换失败修复**：
   - **问题现象**：用户切换至本地 Gateway（如 `http://127.0.0.1:3425/v1`）无 Key 时，直接报错“尚未配置翻译服务/请先配置模型服务，再使用要点”，重新保存配置后才临时生效。
   - **根本原因**：`CoreBridge.RunTextTaskAsync` 在网关路由检查中仅检查磁盘持久化的 `settings.TargetsLocalRuntime`，未检查当前激活路由的 `effectiveSettings.TargetsLocalRuntime`；且 `ProfileManager.ToProviderSettings` 拷贝中遗漏了 `AllowLanEndpoints` 权限。
   - **修复措施**：在 `CoreBridge.RunTextTaskAsync` 中引入 `effectiveSettings = routeSettings ?? settings`，优先基于本次调用的动态路由判定本地回环权限与免 Key 许可；并在 `ToProviderSettings` 中补齐 `AllowLanEndpoints` 透传。

3. **模型引擎切换即时刷新与无缝生效**：
   - **问题现象**：在底部栏或设置中切换模型/引擎档案后，工作台有时依然停留在旧模型状态或旧徽标。
   - **根本原因**：底部栏切换引擎时未调用 `TranslateSection.RefreshAfterSettingsChanged()`；且 `TranslateSection` 中的刷新逻辑因存在既有译文（`FinalText` 非空）而被全部阻断；设置窗口关闭或更改 profile 时未向 `MainWindow` 发送更新通知。
   - **修复措施**：
     - 在 `MainWindow.RefreshEngineStatus` 中增加对 `TranslateSection.RefreshAfterSettingsChanged()` 的触发；
     - 移除 `RefreshAfterSettingsChanged` 中对 `FinalText` 的阻断，在非进行态与非要点态下立即根据当前激活档案刷新徽标；
     - 在 `SettingsWindow` 暴露 `ProfileChanged` 事件，并在 `App.xaml.cs` 中监听其关闭和引擎变更事件，即时驱动主工作台与状态栏同步刷新。

4. **要点与译文徽标显示真实档案名与专属标记**：
   - **问题现象**：要点和翻译完成后，徽标显示生硬的“OpenAI 兼容服务”或“本地模型”，无法直观辨识当前使用的是哪个具体引擎或是否处于要点模式。
   - **根本原因**：`TranslationCoordinator` 在计算 `PipelineLabel` 时未优先采用 `textRoute?.Profile.Name`；要点返回数据流未携带具体引擎标签。
   - **修复措施**：
     - `TranslationCoordinator` 统一优先提取用户自命名档案名称（如“DeepSeek”、“Gateway”等）；
     - `TranslationResponse` 增加可选的 `OverrideEngineLabel` 字段；
     - 要点任务完成后，徽标统一规范显示为 `${EngineName} · 要点`（例如 `Gateway · 要点`），切换回译文时平滑恢复为 `${EngineName}`。
