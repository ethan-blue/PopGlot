# 技术翻译质量放行集规范 (Translation Quality Fixtures)

本文档为 PopGlot 技术翻译质量基准规范（R05 交付物），用于规范技术语境下的翻译质量评估、Token 逐字保护、条件与否定语义保全及放行门禁机制。

---

## 1. 语料集结构与分类分布

质量放行集存放于 `tests/fixtures/translation-quality/`，采用人工合成、无个人敏感信息的技术语料，共计 **80 条**，精确覆盖 6 大技术场景：

| 夹具文件名 | 场景分类 | 条目数 | 验证核心与保护重点 |
| --- | --- | --- | --- |
| `01_errors.json` | 英文报错与调用栈 | 15 | 异常名、堆栈文件、行号与错误码逐字符保护；原因解释清晰分层。 |
| `02_commands_paths.json` | 命令行与文件路径 | 15 | CLI 参数、Flag、绝对/相对路径及危险命令完整保护，严禁截断或乱码。 |
| `03_api_code_comments.json` | API 签名与代码注释 | 15 | 代码语法、泛型、函数签名保持逐字保留，仅翻译自然语言注释与文档。 |
| `04_negations_conditions.json` | 否定句与充要条件 | 15 | `unless`、`never`、`cannot`、`if and only if` 等强否定与边界条件语义绝对不得反转。 |
| `05_multilingual_glossary.json` | 多语言与云原生术语 | 10 | Kubernetes、DPAPI、HNSW、GC、Tokio 等核心技术术语统一与规范表达。 |
| `06_ocr_transcriptions.json` | 屏幕截图 OCR 转录 | 10 | 弹窗对话框、任务管理器、IDE、抓包报文及 BIOS 转录文本结构化直译。 |
| **合计** | - | **80** | **全场景端到端覆盖** |

## 2. 字段规范与评分契约

每条语料均包含如下结构化字段：
- `id`：全局唯一用例标识（如 `ERR-001`、`CMD-003`、`NEG-001`）。
- `category`：所属场景类别。
- `source`：英文技术原文。
- `protected_tokens`：**受保护 Token 清单**，译文中必须逐字符精确存在，不得翻译、大小写篡改或丢失。
- `allowed_variations`：允许的自然语言表达变体（不设唯一标准答案，兼容不同符合语境的自然表达）。
- `key_semantics`：关键语义点说明，阐明该句的核心技术事实。
- `scoring_rules`：评分与放行判定规则：
  - `exact_token_match`: `true`（受保护 token 必须 100% 逐字符吻合）。
  - `no_semantic_inversion`: `true`（否定、操作对象、版本限制或危险禁令含义不得反转）。
  - `no_hallucinated_facts`: `true`（不得捏造不存在的技术参数或事实）。

---

## 3. 质量门禁与放行标准 (Release Gates)

在执行自动化校验与人工抽检时，遵循以下分级放行规则：

1. **P0 阻断项（零容忍）**：
   - 任一 `protected_tokens` 发生拼写错误、大小写错乱、丢失或被翻译（如将 `Pod` 翻译为 `豆荚`，将 `rm -rf` 格式破坏）；
   - 否定含义发生反转（如将“切勿删除临时文件”译为“应删除临时文件”）；
   - 危险命令或破坏性操作的限制条件丢失；
   - 存在严重事实捏造或注入幻觉。
2. **准确性与可读性打分**：
   - 准确性评分（1-5 分）：关键技术动作传达是否准确，行文是否符合中文开发者习惯。
   - 可读性评分（1-5 分）：断句是否自然，技术名词与中文连接词是否平滑。

## 4. 离线验证与真实模型授权边界

- **协议与机制验证（已通过）**：
  - 通过 `PopGlot.Windows.PureTests` 执行 80 项语料的 schema 完整性、token 约束自洽性与隔离性验证，0 外发网络请求。
- **真实付费模型端到端质量验证（未验证 / 待授权）**：
  - 依据主规格 `AI-MODIFICATION-SPEC.md`，本次交接不授权调用真实商业付费 API 服务；
  - 真实模型的翻译质量输出依赖用户自行配置可用的大模型 API Key；
  - 在未接入授权商业模型实跑时，质量结论严格标注为“未验证”，绝不虚构基准通过率。
