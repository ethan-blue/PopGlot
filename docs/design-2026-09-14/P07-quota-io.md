# P07 提示词模板配额与安全导入导出设计方案

> **设计日期**：2026-09-14  
> **责任角色**：Pi（W20b 设计先行 / 前端 UI 设计）  
> **依据合同**：`docs/review-2026-09-12/PROMPT-PERSONALIZATION-AND-GLM-HANDOFF.md` §4.3、§7 P07；关联 N08（备份与恢复）、C02（存储安全与防静默破坏）  
> **覆盖范围**：个人模板物理上限与 UI 反馈机制、纯净 JSON 导出安全协议、原子化零信任导入校验流水线。

## 1. 目标与安全红线

### 1.1 设计目标
1. **配额可视化与物理防打爆**：在 UI 层面实时呈现配额使用率（模板数、正文字节数、单字段长度）；接近上限时温和预警，达到上限时物理阻断新增，防止客户端无界增长挤爆内存与存储。
2. **纯净安全的导出格式**：导出的模板文件为独立受控的标准 JSON，**绝对不包含任何 API Key、服务凭据、端点 URL、网络代理、翻译历史或设备标识**；导出前向用户明确做安全声明。
3. **零信任原子化导入校验**：导入外来文件时执行严格的前置流水线校验（文件大小、Schema 版本、白名单变量、配额余量）；只要存在一处非法内容（如未知变量、恶意脚本），整包原子拒绝，绝不向系统注入脏数据。
4. **确定性冲突消解**：当导入模板与本地已有模板存在 ID 或名称冲突时，提供直观的「生成新副本」、「覆盖现有」或「跳过」决策。

### 1.2 安全红线（硬约束）
- **绝不静默截断**：无论是用户输入还是导入文件，超出 8KiB 或超长字段一律明确报错拒绝，严禁悄悄截断文本导致提示词语义残损；
- **绝不自动出网**：导入与导出均为纯本地文件操作，导入完成后不自动切为当前活跃风格，绝对不向任何翻译引擎发送测试请求；
- **损坏文件只读保护**：底层模板存储文件损坏时遵循 C02 合同，锁定为只读隔离，绝不自动覆写清空。

## 3. 导出格式与安全净化协议

### 3.1 导出标准文件格式
导出文件采用统一的 UTF-8 编码 JSON，后缀为 `.popglot-template.json`（单模板）或 `.popglot-templates.json`（批量集合）。

#### 结构规范（Schema 1.0）
```json
{
  "$schema": "https://popglot.app/schemas/prompt-template-v1.json",
  "schemaVersion": 1,
  "exportedAt": "2026-09-14T10:30:00Z",
  "appVersion": "0.1.5",
  "templates": [
    {
      "id": "tpl_7f8a9b2c_4d5e",
      "name": "技术文档精修",
      "description": "专业术语一致，严格保留代码与路径",
      "domain": "计算机软件 / 系统架构",
      "audience": "资深研发人员",
      "instruction": "适用领域：{{domain}}。面向：{{audience}}。严格保持专业术语一致；代码、命令、路径、URL 必须逐字符保留。只翻译自然语言，不增加原文没有的步骤。",
      "revision": 3
    }
  ]
}
```

### 3.2 字段白名单与黑名单安全保障
- **严格白名单准入**：仅序列化 `schemaVersion`、`id`、`name`、`description`、`domain`、`audience`、`instruction`、`revision`。
- **绝对黑名单防御**：
  - 严禁包含 `apiKey`、`credential`、`endpoint`、`headers`、`token`；
  - 严禁包含任何会话历史、源文片段或译文输出；
  - 严禁包含用户本地文件绝对路径。
- **导出前安全告知对话框**：
  用户点击「导出」时，弹出简洁卡片提示：
  `「导出的模板文件包含您编写的提示词规则与领域设定，但不包含任何密钥或历史记录。请确认导出内容不含私人机密后再分享。」`

## 4. 零信任原子化导入校验流水线

### 4.1 校验流水线阶段图
任何外部文件的导入必须完整经过 5 道检验关卡，任意一道失败立即抛出结构化错误并终止流程，绝不产生半写入：

```text
[ 用户选择 .json 文件 ]
          |
          v
[ Stage 1: 文件尺寸与物理预检 ] ----(> 1MiB)----> [ 阻断: 文件过大，超出安全上限 ]
          |
          v
[ Stage 2: JSON 语法与 Schema 版本 ] --(解析失败/未知版本)--> [ 阻断: 格式损坏或版本过高 ]
          |
          v
[ Stage 3: 白名单变量静态扫描 ] ----(含未知 {{...}})----> [ 阻断: 包含非法或非标准变量 ]
          |
          v
[ Stage 4: 文本长度与配额核查 ] ----(正文>8KiB/超限)----> [ 阻断: 某项字段超出限制 ]
          |
          v
[ Stage 5: 冲突消解与原子落盘 ]
          |
          +---> [ 完成: 本地安全合并，零网络，不自动激活 ]
```

### 4.2 各阶段具体规则与反馈文案

1. **Stage 1: 文件物理预检**
   - 导入文件最大尺寸限制为 **1 MiB**；
   - 超过 1 MiB 立即拒绝并报错：`「导入失败：文件大小（{size}）超出安全限制（最大 1 MiB），已取消导入。」`。
2. **Stage 2: Schema 版本与结构合法性**
   - 检查根节点 `schemaVersion`；
   - 若 `schemaVersion > 1`（来自未来版本的客户端）：
     明确提示：`「导入失败：此文件由更高版本的 PopGlot 创建（Schema v{version}）。请将 PopGlot 升级至最新版后再试。」`（绝不猜测反序列化）。
3. **Stage 3: 白名单变量静态扫描（防注入红线）**
   - 遍历导入包中每个模板的 `instruction`；
   - 提取所有不带反斜杠转义的 `{{...}}` 插值；
   - 若发现除 `{{source_language}}`、`{{target_language}}`、`{{domain}}`、`{{audience}}` 以外的任何变量（如 `{{cookie}}`、`{{system}}`、`{{file}}`）：
     整包立即阻断，报错：`「导入失败：模板【{name}】包含未允许的非法变量 '{var}'。仅支持 4 个标准变量，已放弃整包导入。」`。
4. **Stage 4: 配额核验与总量截断**
   - 计算 `当前个人模板数 + 待导入模板数`；
   - 若总数 > 50：
     弹出配额协商对话框，展示可用名额（如 `剩余名额 2 个，待导入 5 个`），允许用户勾选要导入的条目，或者提示先清理本地模板。
5. **Stage 5: 冲突消解模式**
   当待导入模板的 `id` 或 `name` 与本地现有个人模板重复时，提供弹窗选择：
   - **生成副本（默认推荐）**：分配全新 UUID，名称自动后缀 `(导入)`，保留本地原件；
   - **覆盖本地**：更新本地模板正文与字段，`revision` 在本地基线上自增 +1；
   - **跳过此项**：保持本地原样不动。

## 7. 异常分类与退化保护表（Error Classification）

| 异常情况 | 错误码 | UI 呈现形式 | 系统动作与保护底线 |
|---|---|---|---|
| 个人模板数已达 50 | `QUOTA_EXCEEDED_COUNT` | 顶部黄色 Banner 提示已满；新建与导入禁用 | 禁止新增；允许自由查看、编辑已有项、导出、删除 |
| 偏好正文超出 8192 字节 | `QUOTA_EXCEEDED_BYTES` | 输入框下红色字：`正文超出 8KiB 上限` | 锁定保存按钮；输入内容完整保留，不截断任何字 |
| 导入文件 > 1MiB | `IO_FILE_TOO_LARGE` | 弹窗报错：文件超出 1MiB 上限 | 立即关闭流，不执行反序列化，防止内存膨胀攻击 |
| 导入包含非法变量 | `IMPORT_INVALID_VARIABLE` | 弹窗报错并点名具体非法变量 | 整包原子拒绝，不产生任何脏写入 |
| 存储文件物理损坏 | `STORAGE_CORRUPTED` | 醒目危险卡片提示「模板存储损坏」 | 自动隔离为只读 `.corrupt`，回退至内置模板，不覆盖 |

## 8. 验收清单（Definition of Done）

1. [ ] **配额阻断严格性**：
   - 构造 50 个个人模板，第 51 个模板的新建与导入入口必须物理禁用，并提示明确原因；
   - 录入 8193 字节正文，保存按钮必须置灰并显式报错，且输入框内文字不被裁剪。
2. [ ] **导出纯净化检验**：
   - 导出包含复杂个人偏好的模板文件，文本编辑器查看 JSON 产物；
   - 严格审查确认无任何 API Key、设备信息或历史数据泄漏。
3. [ ] **非法变量整包拦截**：
   - 构造包含 `{{source_text}}` 或 `{{user_name}}` 的恶意导入包；
   - 导入执行时必须百分之百被 Stage 3 拦截，明确弹出非法变量名，且本地模板列表无任何变更。
4. [ ] **Schema 兼容性保护**：
   - 将 JSON 文件的 `schemaVersion` 改为 999 导入，系统必须友好提示需要升级客户端，禁止粗暴闪退或崩溃。
5. [ ] **原子化与零网络保证**：
   - 导入过程中断（如强关窗口或取消），本地文件状态要么完全不变，要么完整成功，不存在坏记录残留；
   - 导入全程抓包监听，确认无任何出网通信行为。
