## 一、目标与非目标

### 1. 核心目标
1. **轻量快捷设置检索**：在 `SettingsWindow` 顶栏/侧栏上方引入统一设置搜索框，支持键入中文、英文及常用别名快速检索全部设置项；
2. **平滑精准直达**：命中项时自动切换至对应分区 Tab（通用 / 引擎 / 快捷键 / 隐私与数据），并将目标设置行平滑滚动至视口中央，赋予醒目的短暂聚焦高亮动画；
3. **严格保持既有保存语义防线（G08）**：
   - 搜索、过滤、高亮与页面跳转属于**纯视图层行为**，绝对不触碰当前草稿基线，不改变任何设置项的取值，不产生伪脏标记（Dirty）；
   - 搜索状态下各表单项的编辑仍受既有 `DraftGuardBar` 与底部保存条统一受控。
4. **“恢复本页默认”安全草稿化**：
   - 恢复默认操作仅将当前页面的 UI 表单项重置为出厂默认值的**内存草稿状态**，不立即执行静默写盘；
   - 绝对不清除已保存的 API Key、不删除用户配置的自定义 Profile、不静默扩大出网或自启权限；
   - 快捷键恢复默认前执行冲突探测，若与现有系统键冲突则保留原绑定并如实回显提示。

### 2. 非目标
- 本波不在主窗口工作台增加全局设置快捷搜素（仅限独立的 `SettingsWindow`）；
- 不做全文复杂倒排索引库，采用轻量级内存静态元数据字典，零第三方依赖；
- 不改变既有的跨分区保存条机制（普通分区由底部统一保存条负责，服务编辑器由内联守卫负责）。

## 二、架构设计与索引数据模型

### 1. 静态设置项元数据定义（`SettingSearchItem`）

在 `SettingsWindow.xaml.cs` 中建立结构化的静态检索索引（或抽取为 `SettingsSearchIndex.cs`）：

```csharp
internal sealed record SettingSearchItem(
    string Id,                  // 唯一标识，如 "General.Theme"
    string Title,               // 显示名称，如 "外观主题"
    string Description,         // 说明文本，如 "跟随系统外观或固定深浅色"
    string SectionTag,          // 所属分区：General, Provider, Shortcuts, Privacy
    string[] Aliases,           // 常用同义词/别名，如 ["深色模式", "夜间模式", "暗色", "dark"]
    string TargetControlName,   // 目标 XAML 控件名称，用于 FindName 与滚动定位
    string EffectiveTiming      // 生效时机提示，如 "即时生效" 或 "保存后生效"
);
```

## 三、UI 交互流与视觉表现

### 1. 布局与界面结构（ASCII 线框）

```
┌────────────────────────────────────────────────────────────────────────┐
│ 设置                                                      [—] [口] [X] │
├─────────────────┬──────────────────────────────────────────────────────┤
│ [🔍 搜索设置...] │  通用设置                                            │
│ ────────────────│  ──────────────────────────────────────────────────  │
│ 🔘 翻译引擎     │  外观主题                                 [跟随系统 ▾]│
│ 🔘 通用         │  跟随系统外观或固定深浅色 · 即时生效                 │
│ 🔘 快捷键       │                                                      │
│ 🔘 隐私与数据   │  开机自动启动                               [重新启用] ⬭ │
│                 │  ┌────────────────────────────────────────────────┐ │
│                 │  │ ⚡ 命中项高亮轮廓 (AccentBrush 呼吸动画 1.5s)    │ │
│                 │  └────────────────────────────────────────────────┘ │
├─────────────────┴──────────────────────────────────────────────────────┤
│ 💡 提示：搜索仅用于快速定位，不改变设置项草稿状态。       [放弃修改] [保存设置] │
└────────────────────────────────────────────────────────────────────────┘
```

### 2. 搜索交互状态机
1. **输入触发（防抖 100ms）**：
   - 用户在搜索框中键入文本，例如键入 `"自启"`；
   - 过滤算法执行多字段模糊匹配（`Title.Contains(q) || Aliases.Any(a => a.Contains(q))`）；
2. **命中展示与快速下拉面板**：
   - 搜索框下方轻量弹出匹配结果浮层（`SearchSuggestionPopup`）；
   - 展示条目：“开机自动启动（通用分区）”、“重新启用自启（通用分区）”；
3. **点击跳转与定位**：
   - 用户点击建议项或按下 Enter 确认首项；
   - **步骤 A**：调用 `SelectSection(item.SectionTag)`，平滑切换左侧导航；
   - **步骤 B**：在对应 Section 的 VisualTree 中通过 `FindName(item.TargetControlName)` 找到目标控件；
   - **步骤 C**：通过 `targetControl.BringIntoView()` 滚动 ScrollViewer 使之居中；
   - **步骤 D**：为目标容器挂载 `AccentBrush` 边框高亮动画（闪烁 2 次后淡出归位），引导视线聚焦；
4. **清空搜索框**：
   - 点击搜索框右侧 `(X)` 按钮或按 `Esc`，搜索框文本清空，建议弹层收起，原分区保持不动，不重载页面。

## 四、“恢复本页默认”草稿化机制

### 1. 交互规范
- 在各 Section 右上角或底部提供次要链接按钮：“恢复此专区默认值”；
- 点击后**绝不弹出阻塞式 MessageBox**，直接在界面形成内存修改草稿：
  - 各表单项控件显示为初始默认值（如开关关、下拉切默认）；
  - 页面下方常规保存条唤起：显示“已恢复专区默认（草稿未保存）”，呈现「放弃修改」与「保存设置」；
  - 若用户点击「放弃修改」，界面瞬间还原为修改前的基线状态；
  - 若用户点击「保存设置」，才执行原子落盘。

### 2. 保护原则
1. **凭据安全**：恢复默认**绝对不清空已保存的 API Key**，不碰凭据库；
2. **服务列表安全**：不删除用户创建的自定义服务 Profile，仅重置全局路由；
3. **网络授权安全**：恢复默认不会将“纯离线模式”意外打开为联网，保持最小授权优先；
4. **快捷键冲突预检**：快捷键专区恢复默认前，先尝试调用 `_hotkeys.TryRegisterAll(defaultHotkeys, out var conflict)`：
   - 若冲突，被冲突项标红显示“默认键位被系统占用，保持原快捷键不变”，绝不强制注册导致热键失灵。

## 五、验收清单（DoD）

- [ ] **精确检索**：输入中文名（如“开机”）、英文名（如“startup”）、常用别名（如“自启”）均能在 100ms 内准确匹配到目标项；
- [ ] **精准滚动与高亮**：跨分区点击搜索结果时，导航 Tab 100% 切换成功，目标控件进入可视区且呈现高亮提示；
- [ ] **搜索零副作用**：连续搜索 20 次不同设置项，底部保存条始终保持 Clean（未修改），不产生任何虚假 Dirty 标记；
- [ ] **修改保存原子性**：在搜索状态下修改某个开关，保存条如实捕获修改，保存成功后仅提交该字段；
- [ ] **恢复默认草稿化**：点击恢复默认后，写盘未发生；点击放弃可 100% 恢复；
- [ ] **窄窗自适应**：在 <700 DIP 窄窗模式下，搜索框自动缩窄，弹层自适应宽度，不溢出窗口边界。
