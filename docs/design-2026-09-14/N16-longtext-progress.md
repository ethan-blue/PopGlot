# N16 长文分段进度与预算控制设计方案

> **设计日期**：2026-09-14
> **阶段/层级**：L2 效率完善
> **依据合同**：`docs/review-2026-09-12/PRODUCT-EXPANSION-REVIEW-V2.md` §5 N16；关联 C20（分段与长标识符）、G04（发送透明与授权边界）
> **前置依赖**：`TranslationCoordinator.cs:895-1000`（既有段落切分 `CoreBridge.PlanSegments` 与 `SegmentSessionException`）

---

## 1. 目标与非目标

### 1.1 目标
1. **段落进度可视化**：在长文本被切分为多段翻译时，UI 准确呈现分段执行进度：「正在翻译第 X / Y 段 (已完成 Z 字符)」，取代不可靠的虚假倒计时或静止 Loading。
2. **Partial 片段安全保留**：当翻译在第 K 段因网络中断、用户取消或超时终止时，已经完成的前 K-1 段译文与第 K 段已产出的流式文字**100% 完整保留在视区**，绝不回滚为全白。
3. **显式「续译此段」入口（G04 契约）**：
   - 针对未完成的段落，界面底部提供明确的操作按钮：「从第 K 段继续翻译」；
   - 续译**属于全新发起的显式发送动作**，必须重新经过 `OutboundPolicy` 授权门禁核验，并派发新的 Session ID，绝不进行隐式静默网络续发。
4. **预算耗尽诚实通报**：若文本总长或单个代码块超限触发 `oversized_code_block` 拒绝，以醒目横幅明确告知：「内容超出单次预算（最多 8 段 / 16,000 字符），请缩短或分批提交」。

### 1.2 非目标
1. **全自动无界后台批处理队列**：不建立驻留后台的无限长文抓取与整本电子书自动翻译队列；一次会话严格锁定在 `CoreBridge.MaxSegments` 物理预算之内。
2. **跨段落逆向回滚**：后续段落报错不回滚或重写已经锁定的先前段落译文。

## 2. 交互流与状态机设计

### 2.1 长文分段状态流转
```text
[提交长文本 (> MaxSegmentChars)]
              │
              ▼
   CoreBridge.PlanSegments(source)
              │
      ┌───────┴───────┐
      ▼               ▼
 [超限拒绝]      [成功切分 N 段]
      │               │
  显示耗尽提示        ▼
             循环执行第 Index = 1..N 段
                      │
           ┌──────────┴──────────┐
           ▼                     ▼
     [本段执行成功]        [本段失败 / 取消 / 耗尽]
           │                     │
   更新进度: X/N 段               ▼
   拼接已完成片段          保持已完成片段 (IsPartial=true)
           │               提示:「第 X 段未完成」
           ▼               提供: [续译剩余部分] 按钮 (需重新授权)
   全部完成 -> 终态
```

### 2.2 UI 元素设计规范（TranslateSection & TranslationPanel）
- **进度指示条（SegmentProgressBar）**：
  - 采用轻量分段条（Segmented Progress Pill），以细条色块标识：
    - 绿色：已完成段；
    - 蓝色脉动：当前在途段；
    - 灰色：等待执行段；
    - 橙黄色：中断/部分完成段。
  - 文案标识：`正在翻译第 3 / 8 段 (已完成 38%)`。
- **续译操作栏（Resume ActionBar）**：
  - 位于译文卡片下方，样式为 Secondary / Outline 按钮：
  - 按钮文案：`⚡ 续译剩余段落 (第 4~8 段)`；
  - ToolTip 提示：「将发起新请求翻译未完成的后续段落，不重复请求已完成内容」。

## 3. 验收清单与涉及文件

### 3.1 验收清单
- [ ] **分段显示准确度**：输入 3 段长文本，验证进度文案依次准确跃迁：1/3 -> 2/3 -> 3/3。
- [ ] **断点保留与零丢字**：在第 2 段进行中点击取消，核验第 1 段完整译文保留，两段之间段落边界无粘连或截断。
- [ ] **续译授权消费**：点击「续译剩余段落」，断言触发了一次全新的 `TryClaimSend` 显式授权，且发送的源文仅为剩余切片。
- [ ] **超大代码块阻断**：注入超过单段预算的未闭合围栏代码，验证界面弹出「代码块过大无法切分」友善拦截。
