## 3. 可直接领取的返修任务卡

每张卡先 a：核查当前代码与合同；再 b/c：最小实现与相关 UI；最后 d：针对验证和记录。a 不得成为无限只写文档的终点。先红后绿应来自生产路径或共享纯逻辑，不能在测试中另写一套修好的算法。

### A01 普通保存不得等价于重新授权 Windows 自启【P1；C07】

**证据**：`SettingsWindow.xaml.cs:494` 每次保存调用 `StartupRegistration.TrySet(shellSettings.StartWithWindows)`；后者 `StartupRegistration.cs:247–257` 写 Run 并修改 StartupApproved。修改主题/其他设置且偏好仍为 true，就可能消除用户在 Windows 的禁用，不只有“重新启用”按钮能走该路径。

**改法合同**：拆分“保存期望/修复 Run 路径”与“用户明确请求重新启用”。普通保存不写/删 StartupApproved；优先提供打开 Windows 启动设置的明确引导和重新读取状态。若要采用直接修改 OS 内部状态的方案，先另立技术决策，不把现有私有二进制值写法当稳定 API。不要为修本项新增安装器或购买签名。

**反例/验收**：Desired=true、OsDisabled=true → 只改主题保存，OS禁用原始字节不变；保存其它字段失败同样不改；显式修复走单独入口，取消不写；整个测试用注册表适配器/隔离根，不触碰用户 Run。保存过程所有调用点要测试，不能只测 EnsureRegistered。

### A02 自启命令、路径识别与通知时机【P1；C07】

**证据**：Run 写入 `StartupRegistration.cs:214/247` 均只有引号包住的 executable，没有 `--background`；ReadState 只 Trim 引号再比较，附带参数会被误判旧路径。`App.xaml.cs:199` 先调用 AnnounceBackgroundStartupFailureIfAny，托盘在后面才 CreateTrayIcon；通知方法先删 marker，Notify 在 tray=null 时直接 return。

**改法合同**：单一启动命令生成/解析合同，明确应用路径和 `--background`，旧无参数 Run 迁移仅修本应用项；不能用简单 Trim 当命令行解析。失败 marker 在托盘/通知渠道可用后处理，至少成功排入可见通知/诊断入口后再消费；不能宣称用户已经看过系统可能屏蔽的气球。

**反例/验收**：含空格/中文路径、新旧参数、错误 executable、缺路径、升级换路径；ReadState(writeCommand) 判匹配；触发 background 分支不弹模态错误；marker 在托盘未就绪时仍在，就绪后诊断可查；无启动项的标准用户安装后登录验证留 E3，不能以字符串单测冒充。

### A03 自启失败、回滚和修复按钮的诚实状态【P1；C07/N12】

**证据**：ReadOsDisabled 读取异常返回 false；TrySetCore 清 OS 禁用异常被吞但返回 true；SettingsWindow 修复按钮立即报成功。Save_Click 回滚 ShellSettingsStore.Save 的异常也被吞，仍宣称偏好已回滚。修复按钮未同步持久期望/草稿，可能出现改注册表却放弃表单的歧义。

**改法合同**：结构化逐项结果，区分读取未知/写成功/写失败/回滚失败/需要系统操作，读不到不能推断有效；修复按钮需解释其独立即时动作，或统一纳入保存，不混用。真正写失败保留可恢复脏态，不用旧内存值冒充磁盘已回滚。

**反例/验收**：Run可写+OS状态不可读；Run写成功+后续失败；首次设置保存成功+启动失败+偏好回滚也失败；修复后取消设置草稿。逐项验证内存、磁盘、OS适配器、文案一致，不得只断言返回 bool。

### A04 AllowOnce 撤销、消费和发包的线性化边界【P0；C01】

**证据**：`OutboundPolicy.cs:61` 先 Interlocked.Exchange 再 SendStillAllowed；`111` 只有非一次性授权重读 consent。已发放 AllowOnce 后设置为 Denied，若网络仍开，旧 token 的实时 consent 路径不会拒绝。消费点后还构建 URI/header 才 send，构建失败会烧掉一次许可。

**改法合同**：统一策略代次与 request-bound token；明确撤销、提交 send 的顺序边界。未到 send 提交的被撤销/构建失败请求不消费；已提交的尝试失败也不返还。AllowOnce 可允许原始 Unset，但不能忽略之后的显式 Denied/撤销代次。不要简单把所有一次性授权都要求持久 Allowed，破坏“仅本次”。LiveSettingsLoader 缺失不能无声拿旧快照当实时许可。

**反例/验收**：签发→Denied→send=0；签发→离线→send=0；两个并发 claim→最多1send；构建失败→0send且未消费；send失败→已消费；cache hit→0send未消费；fallback前撤销→不再发；撤销在线性化点之后不得声称数据从未发送。用可控屏障/假时钟，不靠 sleep 猜竞争。

### A05 所有关闭入口与隐藏副作用【P0/P1；C05】

**证据**：HandleHotkey ClosePanel 调用 `App.CloseActivePanel:813`，后者仅 Hide；显式关闭快捷键不等价 X 的取消。`TranslationPanelWindow:773` 完成自动复制只有 gate/settings 判断；`TranslationPanelStreamGate:131` 不含可见性，隐藏窗口仍接受更新，故自动隐藏后完成仍可改剪贴板。

**改法合同**：明确 HideDueToBlur 与 CloseByUser 两种意图；用户关闭统一取消且可恢复，自动隐藏可继续但禁止自动副作用。副作用由会话/epoch/可见性/资格统一批准；在剪贴板实际提交边界复查，不能只在异步函数入口看一次。恢复不得补发隐藏期间错过的 auto-copy。

**反例/验收**：假剪贴板=sentinel，流式→失焦隐藏→完整结束，仍sentinel；X/关闭热键/Alt+F4分别取消、history新增0、恢复send不增；隐藏→恢复不补写剪贴板；隐藏发生于复制重试等待中也不写；普通可见完成自动复制最多一次。

### A06 Esc、最近恢复与退出所有者【P1；C05/N01/C12】

**证据**：浮窗 OnPreviewKeyDown 一进 Esc 即 Handled/取消，没有先区分菜单/IME；查词只在 Streaming/Finalizing取消，Acquiring/Connecting等阶段会仅Hide。RestoreRecentSurface 总优先 panel，不比较哪种窗口最近访问。新 panel 直接 DestroyActivePanel，不满足 N01 多会话保存。QuickSearch.ForceClose 有定义但在应用退出未显式设置；Shutdown是否完整清理属于需验证项，不能直接断言无法退出。

**改法合同**：Esc优先临时控件/组词；其次所有活动阶段取消；终态隐藏。最近恢复使用统一最近访问元数据，不按固定类型偏好。N01 的5会话/2MiB/30分钟、图像释放、工作台接续按同一仓库实现；先完成合同，不能把只保留两个 Window 实例标成 N01 完成。退出统一守卫一次处理活动任务/设置草稿，随后显式释放窗口、CTS、事件、图像、TTS。普通退出不能无提示强丢设置草稿；系统注销另走有界路径。

**反例/验收**：打开语言菜单Esc只关菜单；IME Esc不取消翻译；Connecting Esc取消；panel→查词→恢复选查词；第6会话按容量合同淘汰；hidden图像终态释放；设置脏态退出取消仍可编辑；确认退出所有活动token取消。真实焦点/注销留 E3。

### A07 围栏语法与“逐字节”声明修正【P0 保真；C04】

**证据**：ToPlainText与RenderToFlowDocument都只用 StartsWith("```")翻转状态；不记起始围栏长度和符号。新增“四反引号测试”只测普通文字中间含反引号，没有测块内以三反引号起始的一行。

**确定性输入**：外层四反引号，内部三反引号应当是代码内容。用字符串 fixture 避免文档围栏歧义：

```text
输入（转义表示）："````\n```\n  x  \n````\n"
期望纯文本："```\n  x  \n"
现算法会把内部三反引号误作结束，并将后续代码按自然语言处理。
```

**改法合同**：共享有界分词/结构识别，追踪 opener符号、长度和允许缩进，closer遵守对应合同；覆盖三/四/更长反引号、波浪线围栏、块内较短围栏、关闭行后非法文本、空/未闭合块。选定 Markdown 支持范围并写入合同，不用多处不一致正则修补。

**验收**：纯文本、视觉块复制、Markdown原文三路径一致且不丢内部字符；LF规范化明确属于“除换行规范化外保真”，不能同时宣称原始CRLF字节不变。全空白输入也遵守换行合同。注释与测试均修正，不靠删末尾换行验收。

### A08 有界读取、损坏保护和可恢复重载【P1；C02】

**证据**：FileInfo.Length后仍File.ReadAllText，文件增长窗口没有累计限制；Corrupt不在LoadBlocked内，备份失败被吞。TryPersist另写.bak提供部分保护，故**此处不能宣称已证实词条丢失**，但“备份失败也允许突变”与安全恢复合同不一致。Load私有且只构造加载，界面文案“重试”不代表现实例真的会重新加载。

**改法合同**：单句柄读取/累计上限/严格UTF-8和schema检查；损坏默认只读，只有备份校验成功且用户明确选择恢复/新建才允许改变原库。所有IO失败结构化，不把每种IOException都说成文件锁。重试加载先准备快照，成功再提交，清掉错误态；保留现有选中ID。

**验收**：静态超限、读取中增长、含有效词条后截断、备份失败、只读ACL、磁盘满、文件锁解除后同窗口重试；所有失败原文件hash不变，不能先删真实文件“试一试”。库页提供安全重试/导出原文件，不要求用户自行删除未知内容。

### A09 日志白名单与生产导出接线【P0 隐私；C03】

**证据**：BuildEntry仍读取自由形式StackTrace并用Sanitize黑名单；非Users目录/项目名可保留。SanitizeForExport在apps生产目录仅有定义，当前搜索只见测试调用。不能将“新增 helper”报成“导出边界已接入”。

**改法合同**：默认只记录结构化受控字段；如果需要栈，提取受控模块/方法标识且去掉全部文件路径，不直接信任可重写异常StackTrace字符串；第三方未知字段省略。对实际日志查看/导出逐入口定位接入；不存在产品导出功能时据实写“不适用/未实现”，不为证明helper新增上传通道。

**验收**：异常message、Data、InnerException、可重写StackTrace分别注入合成原文/秘密/任意盘符项目路径，落盘不可恢复；日志轮转与并发仍有界；从实际导出入口验证，不只直接调用Sanitize；不把本轮真实配置内容拿来脱敏测试。

### A10 异常恢复的可证明边界与重启交接【P1；C06】

**证据**：所有InvalidOperationException均返回可恢复；_degraded只在异常处理链出现，没有对所有请求入口统一阻止；RestartApplication先释放互斥体、启动新进程，之后ExitApplication才清热键和旧实例资源，新实例可能抢资源失败。这里是源码时序风险，不是本轮真机复现。

**改法合同**：业务预期错误在局部边界转Result；全局只接明确受控可恢复错误，泛型InvalidOperationException不能一律吞。熔断进入协调器统一拒绝新任务，取消所有入口在途，不靠禁全局热键代替禁按钮/托盘/已排队回调。重启需要有界清理和新进程握手，禁止先释放单例锁后让两个有效实例重叠；重启失败显示真实结果且保留安全退出路径。

**验收**：一次未知InvalidOperationException→熔断；已知可恢复业务错误→本地反馈；15秒风暴→一次总通知；主窗/托盘/快捷键全部新send=0；模拟旧进程清理慢、新进程启动失败、重复重启；无通知风暴、无重复热键注册。真机重启需获准的测试实例，不操作用户应用。

### A11 可独立验证的纯逻辑宿主【P1；C00】

**目标**：不让真实应用在运行成为全部验证的单点阻塞。

**约束**：现有全套守卫保持，不给它加 skip guard，不用改进程名躲守卫。单独建立只加载必要纯逻辑的测试项目/宿主，不调用App.OnStartup、真实Core配置、Credential Manager、热键、剪贴板或真实注册表。复用生产函数/依赖注入，不能复制修复算法到测试。

**交付**：先列每组测试实际资源依赖，再分为 pure / isolated-WPF / native-loopback / E3；纯逻辑宿主启动有路径与发送器守卫；即使只测纯逻辑也不碰真实配置。WPF需统一一个STA Dispatcher/Application所有者，不跨线程复用Application资源；把先前Application错误独立调查，不假定退出PopGlot就能治好。

**验收**：用户PopGlot运行时pure可跑且系统副作用0；现有完整宿主仍exit3；无实例时完整宿主运行真实全套且退出码反映失败；后台测试任务有总超时，退出能取消/清理。禁止为了隔离拆掉难测断言。

## 12. 复核补充缺口（2026-09-13 第四次 V 轮，原样下达）

本轮仍有 6 个明确缺口，涉及 V03、V05、C09，不能判定"全部返修完毕"。

1. V03：保存基线仍然取自"未保存的表单"——失败后 _settingsBaseline = CaptureSettingsDraft() 读取控件（含刻意保留为 true 的启动意图），磁盘 false、比较基线 true；用户拨回 false 反而无法回 Clean，其他字段改后恢复可能让表单变 Clean 掩盖待重试。要求草稿与已提交基线分别构造；回滚也失败时显式保留待重试状态，不能仅靠表单差异判断。验收：连续失败、第三次成功、主动放弃、其他字段修改后恢复，每步核对磁盘、草稿、基线和保存按钮。

2. V05：唯一就绪事件会立即销毁（using 作用域），父进程可能完全错过；父进程只检查 TryOpenExisting 成功，没检查事件是否已被 Set——对象存在不等于就绪确认。要求父进程在启动前创建并持有事件；子进程到边界后打开并发信号；父进程检查信号状态；句柄在交接结束后统一释放。验收：已创建未 Set 不得通过；子进程先 Set、父进程后等仍能收到；其他尝试的事件不能通过。

3. V05：启动调用超时后仍允许再次启动——超时路径返回 LimboUnconfirmed=false，驱动器允许重试而第一次启动任务可能还没返回；continuation 丢弃 terminateAndConfirm 的清理错误。要求启动任务未完成时标记交接未确认禁止后续启动；迟到进程终止结果被观察、保存并影响交接状态；明确旧进程退出时谁负责迟到任务。验收：首次 spawn 被阻塞时无论是否选重试，启动次数保持 1；迟到清理失败不能解除禁止。

4. C09：测量又变成"等进程退出之后才观察就绪"——生产适配器先 WaitForExit，就绪数值包含退出后耗时。要求分开启动进程/观察就绪/等待退出及检查退出码；就绪观察在子进程运行期间进行；非零退出仍使样本失败但不拿退出时间替代就绪时间。验收：相同时间生成 marker、立即退出与延迟两秒退出，就绪耗时应基本一致；marker 后非零退出仍判失败。
