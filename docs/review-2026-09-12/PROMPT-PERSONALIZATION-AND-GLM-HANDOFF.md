# PopGlot 自定义 Prompt、个性化创新与 GLM5.3flash 执行合同

> 日期：2026-09-12；状态：SPECIFIED_NOT_IMPLEMENTED。
> 先读 [统一入口与最终规则](README.md)。本文件只新增规格和可复制指令，不配置模型、不改应用实现、不启动持续任务。

## 1. 直接回答：能不能有自己的 Prompt 和想法

可以，且值得做，但要把两件事分开。

| 对象 | 目的 | 可以自定义 | 不能靠 Prompt 获得的能力 |
|---|---|---|---|
| 开发 PopGlot 的 GLM5.3flash | 按合同实现、测试、接力，提出改进建议 | 工作角色、每轮任务、交付格式、检查清单 | 自动获得工具权限、真实测试环境、无限上下文、后台调度或发布授权 |
| 使用 PopGlot 的用户 | 让译文符合个人语气、场景、术语偏好 | 翻译风格、领域、受众、用户主动填的背景说明 | 改网络目的地、读取电脑、执行命令、自动采集历史、改变固定输出协议 |

“AI 有自己的 idea”在这里应体现为提出具体可验证的产品提案，而非自行修改规则。开发模型可建议更好的布局与流程；产品可提供可编辑的场景模板和本地偏好卡。所有自动学习、追加上下文和二次请求都必须是单独显式能力，不能藏在 Prompt 里。

本报告按用户指定名称 GLM5.3flash 编写，不据此假设它的实际 API model ID、上下文长度、价格、工具调用或视觉能力。本轮未核实该名称对应的具体服务型号。执行宿主若支持持久系统指令，把第 10 节工作合同放入该位置；否则作为首轮用户指令，每轮携带任务胶囊。不能把本 Markdown 当成可导入 API 配置，也不能声称已设置成功。

## 2. 当前源码具备什么，缺什么

本轮只读入口：

- `crates/popglot-core/src/provider.rs`：`TranslationRequest` 当前字段为 input、languages、include_explanation；`StreamPromptBuilder` 生成 provider-neutral 的 system_instructions 与独立 JSON user_payload。
- 同文件 `stream_system_instructions_unchecked`：固定文本优先、随机 delimiter、metadata JSON 合同；原文置于单独数据消息。另有 legacy JSON `system_instructions` 路径，不能改流式后忘了非流式。
- 同文件四协议适配分别使用 system/message、instructions、system、system_instruction 等协议位置；未来沿用单一编译结果，不能每个协议自己拼用户 Prompt。
- `crates/popglot-core/tests/prompt_contract.rs` 与 `tests/fixtures/prompts` 已提供结构/分片/注入 fixture 入口；现有合成输出不能证明真实模型遵守个人风格。
- 检查 `ShellSettings.cs`、domain 模型和设置窗口相关字段，未确认有完整的用户模板编辑→保存→请求→版本追踪链。**现有内置 Prompt 不等于已有完整自定义功能。** 实施前再次全链检索，若已有部分实现须复用，不重复造服务。

额外风险：现有流式指令要求第一字符不能是空白，但正文可能从缩进代码开始；需要在 P03/C04 中统一“传输包装不添加前言”与“正文自身前导空白必须保留”，不可沿用冲突指令。现有 MAX_MODEL_OUTPUT_TOKENS=1200 是源码值，不等于所有输入都能完整返回；P07/N16 必须覆盖带偏好后预算与截断，不通过提高模型输出上限掩盖整体限制。

JSON 分离源文有助于边界清晰，但不构成抵御模型提示注入的数学保证。真正的安全边界是程序不提供工具执行、发送许可不由模型决定、严格解析/校验、输出保留不完整标记。

## 3. 产品形态：轻入口、深编辑，不增加一块聊天后台

### 3.1 默认体验

主翻译区语言旁提供一个次要“风格：忠实翻译”入口，默认无需配置。浮窗放更多菜单或响应式工具行，不继续挤压标题栏。最近使用最多 5 项，仅改变下次请求；点击风格不自动重译。

内置三个基础风格：忠实翻译、自然表达、正式书面。用户可以复制内置风格为个人模板，不能直接覆盖内置原件。应用更新不得覆盖个人版本，重置只恢复本次编辑草稿，保存才生效。

管理入口位于设置的“翻译服务”邻近子页“翻译偏好”，不是新增顶级“AI 工作台”。资料库继续负责术语；模板仅引用明确选定的规则，不复制一套词库。服务/风格是两个选择器，风格不得偷偷切服务。

### 3.2 模板编辑页面

宽布局为模板列表 + 编辑区，窄布局为列表/详情前进返回。编辑区依次为：名称、适用场景、简短说明、偏好文本、变量帮助、适用能力、预览/试译。底部独立保存条：未保存状态、取消、唯一主要“保存”。删除与保存分离。

偏好文本提示示例：“用于技术文档，术语一致，保持否定与条件，不增加原文没有的步骤。”不要把系统 Prompt、API Key 和请求头堆进普通页面。高级区只读展示编译后的安全层摘要和将发送的个人内容，不开放原始协议覆盖。

试译是次要动作，写明“将向〈服务〉发送示例及此偏好，可能计费”；需要真实调用授权。保存、切选项、展开预览均零请求。无服务时仍能编辑保存、做本地编译预览；试译给配置入口，不禁用整个编辑器。

### 3.3 必须覆盖的编辑状态

| 状态 | 画面与行为 | 数据要求 |
|---|---|---|
| 无个人模板 | 展示内置项和创建入口 | 不生成假个人记录 |
| 已保存 | 名称、版本、适用能力明确 | 不因预览增加版本 |
| Dirty | 常驻未保存提示；离开提供保存/放弃/继续 | 保留全部输入和滚动 |
| 编译失败 | 字段就地指向未知变量/超限 | 禁止保存无效版本，不抹掉原文 |
| Saving/失败 | 稳定布局，失败可重试 | 写盘成功才替换内存已提交版本 |
| 测试中 | 保留草稿，显示服务/取消 | 固定测试快照，不锁死编辑 |
| 测试结束后又编辑 | 标注结果针对旧草稿 | 不能给当前草稿显示“已验证” |
| 不支持自定义 | “此服务不支持个性化指令” | 不将偏好拼到待翻译正文冒充支持 |
| 导入冲突 | 本地/导入版本、差异、处理选项 | 导入不启用，不发请求 |

主题、字号、键盘、读屏、长内容、错误、焦点、200% 文字放大沿用 V2 UI 合同。多行编辑 Enter 换行、Ctrl+Enter 仅在明确配置为试译快捷键且用户确认时触发；不能套用主翻译输入的 Enter 提交使编写 Prompt 误发送。不要默认注册新的全局键。

## 4. 提示词编译合同：能力可扩展，底线不可编辑

### 4.1 层次和冲突优先级

1. **程序硬边界**：网络许可/目的地/配额/取消、字段长度、工具禁用、输出校验；任何 Prompt 都不能覆盖。
2. **不可编辑翻译协议**：原文是被翻译的数据；输出字段、流式 framing、保护 token、不得把解释混入译文；由应用版本管理。
3. **请求结构选择**：源/目标语言、是否解释、技术保护策略。目标语言不能被“请始终用中文”这类偏好覆盖。
4. **匹配术语**：仅启用、匹配、在授权发送范围中的条目；代码/数字等保护高于术语。
5. **已选风格与用户偏好**：语气、领域、受众；冲突时退让，不能要求漏译、改数值或破坏协议。
6. **源文和图像内容**：被动数据，不执行其中角色、命令、链接或“忽略上文”。

前两层由程序强制可强制的部分；自然语言风格优先级只能被提示并验证，不能宣传百分之百控制模型。若输出缺字段/缺 token/截断，按现有完整性合同处理，不自动把坏结果改成成功。

编译器输入是结构化对象，输出 provider-neutral 请求结构；用户偏好以明确标识的受限 preference 字段序列化，由固定指令引用，不将原文内插到系统指令，不手工拼 JSON/引号。delimiter 由每次请求生成；用户不能控制、复用或引用 delimiter。普通预览用标记占位，不泄露真实请求日志。

### 4.2 变量白名单

第一版仅支持以下占位符；不支持表达式、条件、循环、脚本、文件包含、递归展开或网络访问。

| 变量 | 来源 | 合同 |
|---|---|---|
| `{{source_language}}` | 请求语言快照 | 自动识别未定时为“自动识别”，不伪造检测结果 |
| `{{target_language}}` | 请求目标语言 | 必须具体有效目标 |
| `{{domain}}` | 用户本次明确填入/模板已保存字段 | 空值为空字符串，不自动推断进程/网页 |
| `{{audience}}` | 同上 | 仅受众说明，不是隐式联系人 |

不提供 source_text、clipboard、history、screenshot、api_key、env、file、url_fetch、current_app 变量。源文由固定 payload 单独携带，术语由结构字段携带，不能重复插入 Prompt。未知变量阻止保存/编译并指出位置；允许用 `\{{` 表示字面 `{{`，单次扫描处理，替换出来的内容永不再次展开。源文本中的相同字符完全不参与变量解析。

模板正文可以包含任意普通语言；明显要求关闭保护/更改协议的内容给“与固定规则冲突”提示和说明。启发式检测不应拒绝包含这些词的普通讨论，也不能作为安全证明。用户仍可保存普通自由偏好；是否真的遵守通过试译与输出校验判断。

### 4.3 配额、版本和存储（新功能初版目标）

| 项目 | 上限/默认 | 超限行为 |
|---|---|---|
| 个人模板数 | 50；内置项不占用 | 阻止新增，允许查看/导出/删除 |
| 名称 | 64 个 Unicode scalar values | 字段错误；不按 UTF-16 截一半 emoji |
| 简短说明 | 256 scalars | 字段错误 |
| 偏好正文 | 8KiB UTF-8 | 阻止保存，不静默截断 |
| domain / audience | 各 256 scalars 且各≤1KiB UTF-8 | 字段错误 |
| 单次展开个人层 | ≤12KiB UTF-8 | 发送前明确拒绝 |
| 个人模板存储文件 | ≤4MiB；总量含保留版本 | 读取前限额；损坏只读，不覆盖 |
| 每模板保留版本 | 当前 + 最多 5 个旧版本 | 成功保存后只清本模板最老版本；删除前展示保留策略 |
| 最近列表 | 5 个模板 ID | 删除模板后剔除，不保留秘密副本 |

与 N06 术语≤16KiB 上限叠加，但不是“允许无条件多发 28KiB”。最终输入仍受 provider 的请求总字节/上下文/输出预算约束，任一超限必须发送前失败；未知上下文不能从模型名猜。发送 preview 给字符/字节估计，不冒充精确 token 或价格。

记录至少含 schemaVersion、id、name、description、instruction、domain、audience、enabled、revision、createdAt/updatedAt。业务拥有者优先放 Rust domain/core，WPF 通过既有桥接编辑；复用当前安全原子持久化设施。P01 先写 DTO/ABI/迁移合同，具体文件结构须按真实代码确认，不擅自修改共享 C ABI 布局。新增能力需版本化/兼容测试。

无旧字段时使用内置忠实翻译；坏模板隔离后回退内置并告知，不静默丢弃。导入未来 schema 拒绝而非猜字段；失败保持原文件 hash。版本号每次成功保存内容变化递增；内容未变不生成版本，失败不递增。

删除模板需要说明旧版本也被删除、历史结果仍保留；显式删除不另存内容到 tombstone/日志。已启动请求保留内存快照直到结束，删除不声称撤回已发送内容。导出的备份由用户保管，应用不能保证外部副本消失。

### 4.4 请求、历史、缓存的一致性

- 提交冻结 templateId/revision/编译策略版本、偏好值、语言、术语版本及服务；A 请求中编辑模板得到 B 版本，A 显示旧版本，不突然换标签。
- 新请求替换旧请求遵守 epoch；重复点击试译不启动相同并发请求。试译默认不入普通历史，不触发自动复制、收藏或 TTS。
- 缓存 key 必须区分有效偏好内容/编译版本、语言、服务/协议/model/端点、解释与保护策略、匹配术语；内容 hash 仅内部计算，不进入普通日志。
- 默认历史只附模板 ID、名称、revision、策略版本，**不额外保存完整自定义 Prompt 正文**。旧模板可用时允许查看对应保留版本；版本已淘汰时写“原偏好版本不可用”，重新翻译需明确选择当前版本，不能冒充原设置复现。
- 试译详情可以由用户显式复制本次偏好和样例，提示敏感性；安全诊断导出默认排除这些内容。关闭历史不通过 Prompt 功能另写草稿。
- 纯 HTTP 翻译引擎若没有个性化能力，显示 unsupported。不得把自定义指令加到 source 前面发给免费翻译，然后把它翻译出来当功能成功。

## 5. 可直接作为内置示例的偏好文本（不是系统 Prompt）

这些是待实现模板的示例内容，现在不写入应用。均服从固定语言、保真和输出协议；不能直接替换 provider.rs 全部指令。

### 忠实翻译

```text
忠实传达原文含义，保持信息、否定、条件和语气强度。不增补背景，不把推测变成事实，不擅自省略。目标语言为 {{target_language}}；在不改变原意的前提下自然表达。
```

### 技术文档

```text
适用领域：{{domain}}。面向 {{audience}}。专业术语保持一致；遵守已提供的术语规则。代码、命令、标识符、路径、URL、版本、数值和单位不得擅改。只翻译自然语言，不增加修复步骤。原文歧义若需说明，仅在允许的独立解释中简述。
```

### 商务邮件

```text
使用自然、礼貌、正式但不过度客套的 {{target_language}}。保持原文承诺、责任主体、金额、日期、条件与请求强度。原文没有称呼、结尾或承诺时不新增。领域：{{domain}}；受众：{{audience}}。
```

### 日常自然表达

```text
使用目标语言常见而自然的表达，避免生硬逐词对应；保留人物关系、情绪、否定和信息完整性。不要为了流畅改写事实，不自动添加网络俚语或不符合原文的亲密语气。
```

### 学术阅读（后续候选模板，不承诺专业审核）

```text
领域为 {{domain}}。保持论证层级、假设条件、概率、不确定性与引用标识，不把相关性强化为因果性。术语使用一致译法，保留原文谨慎措辞，不增加外部文献或结论。
```

“润色重写”“总结”“解释代码”“回答问题”不是翻译风格。如果以后支持，必须有独立动作、结果类型、来源标识和验收，不能以模板之名悄悄改变翻译产品的基本承诺。

## 6. 有价值但受控的创新方向

| IDEA | 用户问题与方案 | 首次落地/边界 | 怎么验证价值 |
|---|---|---|---|
| I01 场景偏好卡 | 每次重复设置语气；保存“技术阅读/邮件”等个人模板 | P01–P05；用户主动选择，无进程识别 | 换场景操作数，译文是否符合用户盲评偏好 |
| I02 发送前可理解摘要 | 不知道图片/背景/术语发到哪里 | P04/P06；显示实际服务和数据类别，可展开；不每次强制多一道确认 | 用户能说清发送内容；保存/预览请求数为 0 |
| I03 一次性背景便笺 | 同句在不同语境译法不同 | P06 可选 2KiB UTF-8，默认空、不持久化；显式包含在本次发送预览 | A/B 语境区别，下一请求/历史不会隐含携带 |
| I04 本地术语纠正闭环 | 模型重复译错专业名词 | N06/N15；用户确认把编辑提升为术语，不自动学习所有改字 | 下次匹配正确；未批准修改不进入请求 |
| I05 来源与版本标识 | 换服务后不知道旧结果来自哪里 | N10/P05；结果详情标服务、模板版本、人工版本 | 修改设置时旧标签不变；不会假称新服务生成 |
| I06 渐进式复杂度 | 新用户被引擎参数吓退 | UI04/P04；普通页面少选项，高级才展示协议摘要 | 新手完成一次配置且不必理解 SSE |
| I07 可恢复优先 | 意外失焦/关闭造成重复翻译 | N01；有界内存恢复，零额外 send | 误关恢复成功率、重复发送数 |
| I08 个人质量样例夹 | 用户想比较模板是否更适合自己 | 后续研究；用户手动添加非敏感样例，显式批量调用与预算，不默认采历史 | 可复现比较，不用单个模型自评当结论 |
| I09 AI 辅助写偏好 | 用户不会写 Prompt | 后续研究；用户描述→显式一次生成建议→人工采纳，不自动改模板；另外说明接收方 | 采纳率/误改率、取消不保存、拒绝出网仍可手写 |

I01–I07 已映射到现有规格，不生成重复实现工单；I08/I09 不进默认队列。对于新想法，用“问题、受益人、当前证据、最小方案、权限/数据变化、依赖、验收、回退、是否待决策”写一页提案。没有证据时写假设，不捏造用户研究数据。

### P01 模板领域模型、版本与安全存储【L2；依赖 C02 存储合同、N12 配置版本】

目标：能保存用户模板且不损坏既有数据。入口：domain 设置、core profile/存储、FFI DTO、ShellSettings/SettingsWindow；先定位既有所有者。

步骤：列数据模型与默认迁移→定义字节/字符限额→实现校验及原子写入→实现版本保留/删除→绑定显式保存结果。没有 UI 的纯合同子包可先完成，不等待整个设置重构。

验收：旧配置首次读取仍用忠实风格；失败保存 revision 不变；第 51 个拒绝；跨 Unicode 边界无截断；坏/未来 schema/超限原文件不变；删除只操作所选 ID；降级无法识别时安全拒绝而非覆盖。交付：schema、迁移表、样例、失败测试、重载证据。

### P02 有限变量与纯编译器【L2；依赖 P01.a】

目标：同一输入稳定编译，不读取环境。入口：StreamPromptBuilder，新增模块只有确实有独立职责时才抽出。

步骤：冻结编译输入→实现单次扫描和白名单→UTF-8 限额→输出结构化偏好→保留不可编辑协议→错误带安全字段位置，不带全文到日志。

验收：4 个变量逐项替换；未知阻止；转义产生字面；domain 内的 `{{target_language}}` 不递归；源文同符号原样进入数据；8KiB/12KiB 边界；编译零 I/O、零网络。交付：编译契约、可读 golden 结构、边界测试；不能只比较自然语言措辞快照。

### P03 四协议和输出保真接入【L2；依赖 P02、C01/C04/C20/C23 相关合同】

目标：一套偏好跨四协议实际发送一致，不破坏流式/非流式。入口：provider.rs 四映射、streaming assembler、FFI 完整性。

步骤：共享编译结果接入→旧 JSON 路径也支持相同语义→禁模板控制 delimiter/metadata→保留正文前导空白→权限在实际 send 检查→输出失败按 Partial/Failed 规则。

验收：四个回环服务器捕获真实 adapter payload；源文只在规定字段、偏好不进凭据/URL、未知协议能力不伪造；delimiter 跨 chunk、缺 metadata、坏 UTF-8、保护 token 重复/缺失、首段缩进；无授权 send=0。合成回环证明结构，真实风格质量留 P08。交付：四协议契约样本、发送计数、解析反例；没有真实凭据内容。

### P04 模板管理、选择、预览与可取消试译【L2；依赖 P01/P02、N12、UI04；真实试译依赖 P03】

目标：不懂 Prompt 的用户也能创建偏好。按第 3 节 UI 状态落实；普通入口不暴露系统协议编辑器。

验收：编辑 Enter 只换行；保存/预览/换模板 send=0；试译显式确认测试范围，取消无后续发送；无服务仍可保存；保存失败草稿完整；重复名称允许但选择按 ID；内置不可删；深浅/窄高/200%字/键盘均可用；试译版本过期时准确标记。交付：状态图、前后截图和可用性记录，不只新 golden。

### P05 请求快照、缓存和历史可追溯【L2；依赖 P03、N01/N05/N07 相关契约】

目标：当前设置不污染过去结果。执行本文件 §4.4。

验收：A-v1 在途改成 v2，A 标签仍 v1；v2 不命中 v1 缓存；相同 ID 但内容不同不共享缓存；删除/回滚模板不修改历史；旧版本缺失重译要选择当前版本；历史关闭不落 Prompt；试译不会进入普通历史/自动复制/TTS。交付：缓存字段表、乱序事件测试、磁盘检查、恢复场景证据。

### P06 场景、匹配术语与一次性背景【L2 扩展；依赖 P05、N06】

目标：有个人化价值而不无意扩大上传。模板 domain/audience 是主动字段；一次性背景按 I03 默认空、≤2KiB UTF-8、只当前请求；新会话默认不继承，显式重试同一快照可保留并预览。

验收：无匹配术语发送0条；只匹配启用规则；背景不进入后续新请求或普通历史；总预算包含编译个人层、背景、术语、源文；受保护代码优先；文本预览不含完整词库；视觉输入无法在本地可靠确定匹配术语时默认不带术语并说明，可先 OCR 后文字翻译，不为匹配而后台上传图片。交付：数据流/冲突矩阵、发送范围断言、用户文案。

### P07 配额、错误、导入导出和退化【L2；依赖 P01/P03/P05，备份子包依赖 N08】

目标：模板不会成为新日志泄露、无界输入或恢复缺口。

验收：导出个人模板前提示内容可能敏感；不带 Key/授权；导入预检、上限、冲突/未来 schema、取消、事务失败原文件不变；未知模型预算 Unknown，不能假称兼容；不支持个性化的服务给明确禁用；调用因输出截断而 partial 不自动重试或换服务；异常不记录模板文本；恢复默认不删除个人库。交付：完整错误码与回退表，合成敏感文本检出测试。

### P08 质量、稳定性与功能放行【L2；依赖 P01–P07 的启用子集、N15、UI07】

目标：证明启用功能不退化，而不是证明模型“永远正确”。

验收：至少沿用 N15 的 80 条非隐私语料覆盖类别，再对每个首发风格至少选 10 条对照；记录实际模型/协议/服务、输入、模板版本、编译版本、时间、失败和人工评审。不发送真实用户内容；live 单独授权目的地/输入/次数/预算。数值、否定、条件、术语、代码为分项，不能用“更自然”抵消失真。未知费用就写未知。

无 live 权限可完成纯编译和回环测试，但真实语义有效性必须“未验证”，不能 P08 全通过。性能记录编译/渲染额外开销而非只报总网络耗时；模板上限/长源/连续切换/取消压力/主题热切换覆盖。交付：当前构建功能矩阵、人工 rubric、原始样例与保留问题。P06/备份延期且未启用时明确首发子集，不将未来全部能力自动算完成。

## 8. 提示词功能的最小上线切片

首切片只包含内置三风格、个人模板基本 CRUD、四变量、固定协议编译、选择和零网络预览、快照/缓存/隐私/错误保护。P01–P05 与 P07 安全相关子包先成立；真实试译能力需要当前服务授权和对应质量验证。

## 9. 给执行模型的任务粒度与阅读策略

GLM 的具体能力未知，因此任务协议不依赖“大上下文一次读懂全部”。每轮一个任务的一个子包，或同一小包中紧密相关的实现和验证；不得同时认领授权、词库、窗口生命周期三个独立状态机。

任务胶囊必须包含：ID、目标、非目标、入口、必须读的合同、依赖状态/证据、用户已有修改、输入/输出、错误与取消、验收、下一步。胶囊是索引不是替代正文；检查发现与当前代码不符要修正定位，而不是照抄文件名。

执行模型可以自行分解局部函数，但不能自行降低 DoD、修改保护规则、扩大任务或给自己发布签字。不要求暴露冗长内部推理，只需外部可核查的判断依据、取舍与证据。

## 15. 24 小时接力的实际工作机制

“24 小时”是希望持续可靠推进的目标，不是一次聊天自动获得定时运行能力。本次未创建调度。未来若另行授权调度，宿主负责唤醒/权限/额度，模型负责从检查点继续，不能把两者混同。

每轮循环：读取→核查授权/依赖→一个小包→针对验证→保存证据与检查点→在批准集合内下一小包。无可执行批准项或需要负责人决定就停止并报告；达到验收闭环就交付，不无限重画 UI。执行者离线不等于任务失败，记录应让下一次能接着做。

落盘至少发生在：第一次定位完成、任务合同确定、每次有意义的可回退修改后、测试失败影响方案时、子包交付时、上下文/额度预警前。未完成报告先保存已有完整章节并列明确剩余目录；不能写“全部完成”再留下待填验收。任何数字预算都是资源控制，不能成为跳过隐私和保真检查的理由。
