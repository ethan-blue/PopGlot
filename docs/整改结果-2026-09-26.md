## R01 列表测试保存旧配置快照

状态：通过（纯逻辑）。界面点击路径未在真机上再跑。

复现：测试开始前保存整份配置，等待期间改模型、地址、凭据修订号、另一个引擎的名称、默认引擎，或删掉目标引擎，结束后仍把旧快照写回去。

根因：`TestProfile_Click` 在 await 之前持有整份 `CoreProductConfig`，完成后写回这份旧对象。

改动：`ConnectionTestRunner` 在测试开始时记下引擎 id、连接版本和凭据修订号。完成时 `ProfileManager.TryPatchVerification` 重新读取最新配置，只在三项仍匹配时改该引擎的验证字段。同一引擎进行中时第二次测试直接返回 Busy；另一个引擎可以同时完成。编辑器写回走同一补丁，不再保存整份旧快照。

文件：`Services/ConnectionTestRunner.cs`、`Services/ProfileVerification.cs`、`Services/ProfileManager.cs`、`Sections/ServicesSection.xaml.cs`、`tests/PopGlot.Windows.PureTests/Program.cs`。

命令：`dotnet run --project tests/PopGlot.Windows.PureTests -c Debug`，退出码 0。日志：本机 scratch `pure-tests.log` 中的 `list connection test patches only a matching engine`。

## R02 导出会覆盖同分钟文件

状态：通过（纯逻辑）。打开文件的按钮没有在真机上点过。

复现：同一秒内两次导出，以及两个并发导出，都会命中 `yyyyMMdd_HHmm` 再 `WriteAllText`，后一次覆盖前一次。

根因：文件名只到分钟，并且用覆盖写。

改动：`ExportFileWriter` 用临时文件写完再独占移动。已存在的路径会换 `-1`、`-2` 后缀。写入失败时删掉半成品，并返回短句，不把长路径放进常驻状态。资料库导出成功后只显示「已导出」，另给「打开文件」「打开所在文件夹」「关闭」。CSV 公式转义仍由原来的 `ExportToCsv` 生成。

文件：`Services/ExportFileWriter.cs`、`Sections/LibrarySection.xaml`、`Sections/LibrarySection.xaml.cs`。

命令：同上 PureTests，退出码 0。用例：`history export does not replace an existing file`、`concurrent exports keep the original bytes`、`failed export removes the partial file`。

剩余：桌面上的真实资源管理器打开动作未在本轮点过。

## R03 清空与删除的恢复

状态：通过（存储与撤销票）。界面动画和窄窗未截图。

复现：单条删除要在 3 秒内点第二次才生效，清空却是一次完成。

根因：`RequestDeleteRow` 把第一次点击只当成武装。

改动：删除和清空都立刻落盘。成功后给出约 20 秒的内存撤销票，只把本次删掉且当前仍不存在的 id 插回去，不替换之后新增或改过的行。历史写入失败会回滚内存并不发撤销票。只读历史文件、损坏的生词本都不会声称已撤销。重启后撤销票不存在，因为它不写盘。资料库窄于 560 DIP 时列表和详情二选一，详情上有「返回列表」，选中项还在。

文件：`HistoryStore.cs`、`Services/VocabularyStore.cs`、`Services/LibraryUndoJournal.cs`、`Sections/LibrarySection.xaml(.cs)`、`Sections/DataSection.xaml(.cs)`。

命令：PureTests 退出码 0。用例：`library undo restores only the removed rows`、`library undo is not offered when the write fails`。

剩余：没有窄窗截图。撤销条和返回按钮没有用隔离宿主点过。

## R05 Key 和验证证据

状态：通过（纯逻辑与编辑器保存规则）。四种视觉状态没有新截图。

复现：换一把未测试的 Key 后，只要「有 Key」这个布尔值不变，旧的「可用」还会留着。未保存的 Key 测试有机会写进已保存配置。遮罩如果被当成密码发出去也会污染结果。

根因：指纹只含「是否有 Key」，不含凭据修订号。列表测试写整份快照。

改动：`CredentialRevision` 存在配置里，不是 Key，也不是 Key 的哈希。保存或清除 Key 时加一，并清掉对不上的验证标记。未保存 Key 的租约用「当前修订 + 1」，补丁对不上已保存行。保存失败会把 Key 写回去，并拿掉这次的成功标记。遮罩字符不会被送去测试。证据文案是「上次成功」。

文件：`Services/ProfileManager.cs`、`Services/ProfileVerification.cs`、`Sections/ServicesSection.xaml.cs`。

命令：PureTests 退出码 0。同一条连接测试用例检查了未保存 Key 不写回、未测试的新 Key 丢掉旧标记、配置 JSON 不含密钥原文和 SHA-256。

剩余：未填写、已保存、正在替换、已清除的界面对照图没有新拍。凭据库只用了内存替身。
