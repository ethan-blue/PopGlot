## 1. 逐项整改结果

### U01 工作台圆角外框与内部背景（P1）——通过（离屏像素级 + 回归测试）

- **根因**：外层卡片 `Border`（`CardRadius`=10 + 1 DIP 描边）不会裁切子元素；语言栏/页脚单元格自绘 `SurfaceMutedBrush` 方形背景，四个外侧角以方角盖过外框圆弧。`SetStacked` 只重排行列，不调整角部几何。
- **修改**：`TranslateSection.xaml` 四个角部单元格初始 `CornerRadius="9,…"`（= 卡片半径 − 描边）；新增 `TranslateSection.ApplyPaneCornerRadii(bool)`（TranslateSection.xaml.cs:586 附近），横排只圆四个最外侧角、竖排只圆整组顶部/底部，接缝保持直角；`SetStacked` 两个分支调用。内层圆角由资源 `CardRadius` 动态计算，不硬编码主题。
- **行为变化**：卡片四角画布底色透出，外框圆弧不再被方形底色覆盖；横竖排切换后角部即时正确。
- **证据**：
  - 像素级前后对照（`artifacts/ui-ux-review-2026-09-29/pixel-verify-output.txt`）：暗色四角「角内 2px」点 基线=`14161D`（SurfaceMuted 方形泄漏）→ 修复后=`101216`（画布透出）；浅色 `F8F9FA`→`F6F7F9`；竖排 tl/bl 同样成立；弧内 +4/+12px 两版本一致（无过度裁切）。
  - 回归测试：`workbench pane corner cells round the card corners in both layouts`（横排/竖排/切回三态断言）。
  - 截图：`workbench_{dark,light}_1100w_corner_{tl,tr,bl,br}.png`、`workbench_{dark,light}_700w_stacked_corner_*.png`（after/ 与 baseline/ 各一套）。
- 同步检查了规则列表/选项/编辑页：`PromptListItem`、`PromptSectionCard` 子层无自绘背景，无同类问题。

### U02 平面输入/阅读面键盘焦点（P1）——通过（测试 + 像素证据；真机 IME 未验证）

- **根因**：`FlatTextBox` 继承的隐式模板触发器写 `Surface.BorderBrush`，但样式把 `BorderThickness` 置 0，焦点/悬停边框永远不可见；`FlatRichTextBox` 与 `ResultTextBox` 关闭 `FocusVisualStyle` 后同样无任何焦点提示。
- **修改**（`Themes/Controls.xaml`）：
  - `FlatTextBox`：常驻 1 DIP 透明边框（悬停 AccentBorderBrush、键盘焦点 AccentBrush，来自继承触发器）；厚度不变，焦点不引起布局位移。
  - `ResultTextBox`：模板 Border 改为绑定描边/圆角，新增 `IsKeyboardFocusWithin` → FocusBrush 触发器（阅读面只响应键盘进入，不做大面积悬停）。
  - `FlatRichTextBox`：补自定义模板（`PART_ContentHost` + Surface Border），同样的 1 DIP 焦点实线；无模糊光晕、无阴影。
- **证据**：`flat text surfaces paint a keyboard focus line`（三样式静止=透明、聚焦=FocusBrush、1 DIP 常驻）；像素差：输入焦点截图 Accent 族像素 1319 vs 空闲 1076（dark）/ 1366 vs 1119（light）——焦点线真实渲染。截图 `workbench_*_inputfocus.png`、`workbench_*_resultfocus.png`。
- 保留不动：`FormTextBox`/`FormPasswordBox` 原有焦点边框、开关胶囊 `SwitchFocusRing`。

### U03 内置规则单选语义（P1）——通过（真核心测试）

- **根因**：互斥的语气选择用普通 `Button` + `IsActive` DataTrigger 表达，UIA 无选中语义，读屏不可知选中状态。
- **修改**：`PromptSection.xaml` 新增 `PromptChoiceItem`（RadioButton 样式，视觉延续原 GhostButton 选项：选中 = AccentSoft 底 + Accent 边框 + 半粗字，悬停只弱化边框）；模板项改为 `RadioButton`，`GroupName="PromptBuiltinStyle"`，`IsChecked="{Binding IsActive, Mode=OneWay}"`，激活走 `Checked` 事件（绑定回填以 `_activeId` 守卫忽略，避免数据回填被当成操作）；`ActivateTemplateByIdAsync` 失败路径补 `PaintLists()`，选中外观回到数据真值，不保留虚假成功选择。
- **行为变化**：方向键组内移动（WPF 原生 RadioButton 组导航）、Tab 只停选中项；UIA 暴露 RadioButton 选中状态。
- **证据**：`builtin tone choices are radio selection semantics`（真 Rust 核心：勾选切换实际落盘 + 重绘后仅新选中项 checked + SelectionItem pattern 存在）；截图 `prompt_list_*.png`（静止外观与基线整图差异 1.6%，见 §3）。

### U04 删除确认稳定化（P1）——通过（真核心测试 + 像素证据）

- **根因**：删除武装直接改写行内图标按钮（宽度 32→86、Content 换成「确认删除」），布局位移 + 3 秒限时需再次瞄准；编辑器删除按钮同一武装逻辑。
- **修改**：`PromptSection.xaml/.xaml.cs` 全面改为**行内确认区**：
  - 列表行：第一次点删除 → 行内展开 DangerSoft 确认条「删除「规则名」？模板的历史修订版本会一并删除，此操作无法撤销。」+ 固定位置「取消」「删除」按钮；操作列让位、按钮宽度全程不变；**无 3 秒限时**；Esc/取消/切换上下文（激活其他规则、进入编辑器、离开页面、重载）解除；焦点转入确认区，取消后还给该行删除按钮，删除成功后聚焦「添加规则」。
  - 编辑器：`EditorDelete_Click` 在原删除按钮位置展开同一契约的确认面板（`EditorDeleteConfirmPanel`），取消恢复按钮并还焦点。
  - 移除 `_deleteArmTimer`/武装字段与 `DisarmDelete`。
- **证据**：`prompt delete confirmation is an inline strip with no timer`（真核心：按钮宽度/MinWidth/Content 不变、泵过 3.3 秒确认区仍在、取消恢复、确认后模板真被删除）；像素差：确认态 Danger 族像素 528→14878（dark；基线同场景 520→1090 的小按钮染色）；截图 `prompt_list_*_deleteconfirm.png`（after=行内确认条；baseline=86 宽「确认删除」按钮，同场景前后对照）、`prompt_editor_*_deleteconfirm.png`（after 独有）。
- 删除范围说明（历史修订一并删除、不可撤销）保留在确认条与编辑器按钮 Tooltip 中。

### U08 帮助目录悬停覆盖选中（P2）——通过（模板级测试）

- **根因**：`HelpWindow.xaml` ListBoxItem 模板触发器顺序为 IsSelected→IsMouseOver，后者（模板触发器后者胜出）在选中项悬停时把背景改回 SurfaceHover，唯一选中线索丢失。
- **修改**：交换顺序（IsMouseOver→IsSelected），选中背景恒保留；键盘焦点 FocusRing 原有。
- **证据**：`help toc selection wins over hover`（断言最后一个写 Background 的触发器属于 IsSelected——若回退旧顺序该测试失败）；截图 `help_*.png`。
