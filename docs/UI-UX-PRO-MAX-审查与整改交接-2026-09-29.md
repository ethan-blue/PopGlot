## 3. 逐项修改意见与验收

### U01：圆角必须覆盖实际绘制层

根因线索：外层 Border 的 CornerRadius 不会自动裁切内部 Grid/Border 的背景；`SetStacked` 目前调整行列与分隔线，没有调整角部几何。

修改要求：

1. 先分别截图横排和竖排，给每个外露角标出负责绘制的元素；同时检查规则列表、选项切换、编辑页。
2. 优先让父容器统一绘制底色，子层仅绘制必须的差异背景；必须独立绘制的角部绑定到布局对应的圆角。
3. 横排：只有最外侧角圆角；竖排：只有整组顶部/底部圆角。内部接缝不叠加圆角。
4. 如必须裁切，只裁切背景/内容层，几何随尺寸更新；焦点装饰、阴影、滚动条及 Popup 不参与同一裁切。
5. 禁止只加 `ClipToBounds=True`，或通过降低对比度掩盖方角。

验收：普通、悬停、按下、选中、键盘焦点、禁用均保持同一轮廓；光标、中文下沿、焦点线和弹层无裁切。深浅主题各提供规则列表、选项、编辑页及工作台同场景前后截图。

### U02：焦点清晰，不恢复模糊光圈

`FlatTextBox` 的模板只处理占位及禁用；关闭 FocusVisualStyle 后没有容器焦点提示。`FlatRichTextBox` 同样关闭焦点样式。普通 FormTextBox 已有焦点边框，不应重复修。

建议在编辑区外层提供清晰的 1 DIP 实线焦点边界，使用现有 Accent/高对比主题资源；不要添加阴影或模糊描边。只读富文本在键盘进入时也应可识别当前位置。优先复用焦点样式或明确的父层状态，避免每页复制模板。

现有 `SwitchFocusRing` 已存在并被两个开关样式使用。用户说的“朦胧圈”是否仍出现必须重新区分：鼠标点击、Tab 焦点、选中状态、DPI 缩放。不要直接删除键盘焦点，也不要把正常焦点标记当成选中背景。

验收：仅键盘完成输入→翻译→切换译文/要点→复制；始终知道焦点位置。IME 组合文字不裁切，Space/Enter 行为保持。高对比模式下仍可见。

### U03：规则选择使用正确语义

内置规则采用单选语义：优先改为样式化 RadioButton 或单选 Selector，让 UI Automation 自动暴露选中状态。视觉保留紧凑选项，不增加一排说明卡片。当前选中同时用轻背景、明确边框和小勾表达，不仅改变颜色。

验收：方向键按所选控件约定切换，Tab 不陷入循环；读屏能读出规则名、角色、选中状态。保存失败不能保留虚假的成功选择。改变控件类型时核对原激活事件、数据保存和默认规则逻辑。

### U04：删除确认保持稳定

旧的“32 DIP 塞确认文字”已通过扩到 86 DIP 处理，但扩宽本身不是稳定交互。建议使用已有列表内确认区：显示“删除「规则名」？”，附“取消”“删除”，操作按钮位置固定；标题很长时换行，焦点转到确认区，Esc 取消，结束后恢复合理焦点。

明确说明真实删除范围；若历史版本也删除，保留该必要说明。不要为视觉简洁隐藏后果。优先取消 3 秒限时确认，使用显式取消；不要未经设计新增数据撤销机制。切换项目/离开页面时解除确认，避免残留状态和计时器。

验收：连续点击不同项目、窄窗、长名称、键盘确认、删除失败、当前活动规则删除均可恢复；无相邻按钮被挤动或误触。确认后究竟保留何种默认规则必须沿用已有产品契约。

### U05–U06：规则行的语义与宽度

- “使用规则”改用现有勾选/启用图形，星形统一用于收藏。已使用的规则直接显示“使用中”，避免重复操作。
- 每个行操作的 AutomationProperties.Name 带规则名，例如“编辑规则：学术表达”。短 Tooltip 保留，读屏名称可以更完整。
- 名称一行省略；说明最多两行，提供可键盘访问的完整说明或编辑入口，不能仅靠鼠标悬停。
- 操作列保留明确宽度；极窄时将低频编辑/删除放入“更多”，核心选中身份保持可见。不得为了容纳全部按钮把主体字号缩小。
- 50 个自定义规则的性能先量测。当前限额下不因“ItemsControl”字样就强行重构虚拟化。

验收：最长允许名称/说明、中英文混排、无空格长串、空说明、活动项、读取失败均不撑出页面；读屏能区分同名操作属于哪个项目。

### U07、U09、U11：统一窄窗退让顺序

工作台已实现内容宽度低于 720 DIP 的上下布局，以及 620 DIP 以下隐藏快捷键提示。必须保留，不得报告为“没有响应式布局”。不足是组合内容压力仍需验证。

工具栏建议使用明确的 `* + Auto` 列或可重排布局；优先级为：翻译主操作→当前规则/语言→恢复等次操作→快捷键说明。空间不足先收次操作到“更多”，最后换行，不让标题与操作重叠。

资料库状态与操作分行：消息可换行；“打开文件”为主要后续操作，“所在文件夹”放次级操作，“关闭”为图标加完整读屏名。撤销不可因消息变长而被挤出，也不能用省略号隐去部分恢复信息。

设置窗口最小宽度 680 DIP、侧栏 168 DIP，还要扣除内容内边距。引擎列表固定的 132 DIP 状态列需核算剩余名称空间；窄窗先让状态移到第二行，而不是让引擎名只剩几个字。

浮窗按 460 DIP 最小宽度、快速查词按 480 DIP 最小宽度核查，折叠低频工具，保留翻译/停止、语言与当前结果模式。规则名后不重新加模型名；完整请求来源按需查看。

验收：在实际最小窗宽及断点前后各 1 DIP 检查；包括首次使用条幅、长规则名、长引擎名、长状态、无结果和错误。无横向页面滚动、重叠、焦点遮挡；每个功能仍能键盘访问。

### U08：帮助目录的状态优先级

改为选中+悬停的组合状态，或令选中底色保留并以边框/侧标识表达选中。悬停不能覆盖唯一的选中线索。现有圆角行背景保留。

验收：选中项和普通项分别悬停、键盘聚焦；任何时刻能辨认当前文章。检查导航和正文边框只由一层负责，窄窗长标题不压正文。

### U10：设计文档归一

- WPF 布局规格写 DIP，不把网页像素和物理像素混用。
- 色值以 ThemeService 为唯一来源，文档用 token 名称并说明用途，避免重复十六进制值漂移。
- UX_DECISIONS 的“四个分区”和服务页固定左右 Master–Detail 描述需按实际五个分区及列表/编辑流程修订。
- 删除无实测依据的“毫秒级首 Token”“彻底解决跳动”和普遍适用的中英文长度百分比；改为可测量的目标与样例。
- 文案短不等于承诺过度：“保存即时生效”“仅发送脱敏文本”等必须符合实际请求时机和发送范围，未核实不能写成保证。

### U12：阅读与请求状态一起验收

这是验收任务，不是已确认回归。重点场景：请求中切规则/引擎、交换语言、译文与要点互切、历史恢复、离开后返回、取消后迟到结果。

要求：耗时归属于实际结果，请求尚未发生不能显示“0 秒完成”；当前配置与生成旧结果所用配置可区分，但完整模型名无需常驻工具栏。AI 要点能力不足时说明原因，不能让入口像坏掉；启用新请求或费用路径前遵循用户授权。

局部加粗已具备渲染与请求提示相关实现，不能承诺每次真实模型都会生成。验收应区分“收到 **强调** 后渲染正确”与“模型能恰当地生成强调”。禁止显示层猜重点、插入事实或额外发请求。译文与总结都复用 Markdown 语义；代码、链接、列表、表格和普通换行保持。流式终态切换保留滚动位置和用户选择意图，不能通过整个视图淡入淡出来掩盖跳动。

## 5. 统一视觉约束

保留现有字体与功能性色彩，不从技能库随机换主题。技能的移动端 44×44、网页正文 16px 不直接套到 WPF。

| 角色 | 本轮建议 |
|---|---|
| 页面标题 | 保持现有约 20 DIP；紧凑浮窗单独定义，不任意覆盖 |
| 正文/标签 | 现有 13 DIP；译文 14.5 DIP / 22 DIP 行高作为基线 |
| 辅助信息 | 11–12 DIP 只放非关键元数据；错误、状态原因不要靠极小灰字 |
| 表单 | 36 DIP 作为常规单行基线，中文光标实测；多行不固定高度 |
| 紧凑工具按钮 | 28–32 DIP 的角色范围；图形与点击区域分开；不能一律改成 44 |
| 间距 | 4/8/12/16/24 的有限档位；减少无意义嵌套卡片 |
| 圆角 | 沿用 ControlRadius=6、CardRadius=10 等现有 token；状态层共享几何 |
| 焦点 | 清晰实线、无模糊光晕；选中与焦点是不同状态 |
| 文案 | “管理”“检测”“翻译”“取消”；完整含义由上下文和读屏名补足 |

以上是实施建议，不是所有控件已满足的验收结论。对比度用实际前景/背景及透明混合后的颜色量测，不能因 token 测试通过就推断所有组合通过。

1. **T00 基线**：读 AGENTS、git status/diff、最新问题单及本报告；标记已存在改动。记录实际运行构建，不读取真实密钥。为当前问题制作合成样例和修复前截图。
