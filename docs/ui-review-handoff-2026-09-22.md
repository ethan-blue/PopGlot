## 方向

方向是简约，并把界面从助手腔里拉回工具。

平面：页底、卡片、输入、结果都是实色表面，靠 1px 分割线分层。每个视图只有一个主操作。主操作是填充按钮，或是一个明确的按键（浮窗和极速查词的 Enter）。其余操作用描边按钮、文字或图标。

间距走 4/8 网格。新调的空隙只用 4、8、16、24。页边距 16，区块间距 16，卡片内边距 16，同一行控件间距 8，图标和文字间距 8，分组标题到卡片 8。行内上下 12 可以保留（12 是 4 的倍数）。

颜色只用 `apps/PopGlot.Windows/ThemeService.cs` 里现成的 token（`DarkTokens` / `LightTokens`）。未写出的颜色保持现有 theme token，不要在页面里写死色值。圆角保持现在的控件 6、卡片 10、浮窗 12。颜色或圆角若要改，必须标为待确认。本稿不改颜色、不改圆角。

字号沿用现有层级：页标题 20 / SemiBold，分组标题 13 / SemiBold，行标题 13 / Medium，正文 13，说明 12，元数据 11。界面字体 Segoe UI Variable Text、Microsoft YaHei UI。快捷键用 Cascadia Mono、Consolas。

文案用短句，动词放在前面。按钮用两个到六个字。说明一行能读完。

界面里不要出现这些东西：渐变英雄区、玻璃拟态、聊天气泡、营销口号、装饰插画。空状态用一行字，不用居中插图。结果区是上下或左右的文本面，不是对话记录。

共用壳（设置新分区、引擎新行、阅读模式以后都套这套，见文末「扩展」）：

| 部位 | 做法 |
| --- | --- |
| 页底 | `CanvasBrush` |
| 侧栏、底栏 | `SidebarBrush` |
| 卡片、列表 | `SurfaceBrush`，描边 `BorderSubtleBrush` 1px |
| 菜单、说明条 | `SurfaceRaisedBrush` |
| 输入 | `InputBrush`，边框 `BorderStrongBrush` |
| 结果 | `ResultSurfaceBrush` |
| 主按钮 | 底 `PrimaryBrush`，字 `PrimaryTextBrush` |
| 次按钮 | 透明或表面底，描边 `BorderSubtleBrush`，字 `TextPrimaryBrush` |
| 危险按钮 | 描边和文字 `DangerBrush`，底保持表面色 |
| 选中、链接 | `AccentBrush` / `AccentSoftBrush` / `AccentBorderBrush` |
| 次要字 | `TextSecondaryBrush`；占位、时间 `TextTertiaryBrush` |
| 成功、警告 | `SuccessBrush`、`WarningBrush` 及对应 Soft，不拿来当主按钮 |

高对比度仍走 `ThemeService` 现有调色。本稿不改那条路径。

## 矩阵约束（full-matrix）

不要按 77 张图各做一版。代表图上的建议落地后，下面这些情况仍然要成立。

- 浅色/深色：同一套布局。浅色用 `LightTokens`，深色用 `DarkTokens`。`main_window_light.png` 与 `main_window_dark.png`、设置、浮窗、极速查词、触发器都要两套都能读。禁止只在浅色上调完就停。
- 125%、150%、200%：主窗口、资料库、设置、引擎编辑器、极速查词、翻译浮窗在 `full-matrix/` 里都有 Light/Dark 的这三档。200% 时顶栏主按钮、语言行、「译文」「要点」完整可见，文字不叠在一起。放不下就出现滚动，不把控件裁掉。
- 窄窗：以 `main_window_narrow_dark.png` 为准。侧栏收成图标。原文在上，译文在下。目标语言和「译文 / 要点」落到下一行。顶栏仍是风格下拉、「恢复暂存」、填充按钮「翻译」。窄窗不要硬撑回左右分栏。
- 错误态：以 `translation_panel_error_light.png` 和 `translation_panel_error_dark.png` 为准。结果区在「译文 / 要点」旁出现「未完成」。标题是具体失败原因（图中为「模型网络目前未启用」），下面是原因和「检查服务地址与网络后重试」。旁边描边按钮「打开设置」。底栏状态为「需要处理」。错误留在结果区里，不收成会自动消失的提示条。
- 风格菜单展开：工作台、极速查词、翻译浮窗都能弹出与 `pages/13-style-menu-expanded.png` 相同结构的菜单。矩阵里对应 `style_menu_open` 与 `style_menu_popup`。菜单贴边时向内翻，不换一套样式，也不被窗框裁掉文字。
- 编辑器窄宽、长模型名和遮挡：`settings_compact_provider_light.png` 与 `settings_compact_provider_dark.png` 里，固定底栏切过「文字模型」输入框，浅色和深色一样。这是要改的遮挡，不是可保留的构图。控件要么整段留在底栏上方，要么整段滚到折页下，不能只露出半个输入框、半行单选或半个按钮。`service_editor_compact_light.png` 两列改单列，底栏仍是「删除引擎 / 取消 / 保存修改」。`service_editor_long_model_light.png` 的长模型名和推荐芯片必须停在自己的列里，用省略和悬停全文，不能画进旁边一列。`service_editor_light.png`、`service_editor_dark.png` 以及 125%、150%、200% 四套图用同一条遮挡规则。`translation_panel_min_*` 仍能看到输入、「译文 / 要点」和关闭。`capture_overlay_light.png` 与代表图是同一条说明条。

## 待确认

下面这些是现有产品事实。建议若和它们冲突，以这里为准，不要在实现时悄悄换掉。用户确认前，整份稿都不要当已通过。

1. 主题保持三档：系统 / 浅色 / 深色。不改成两档，也不改名。
2. 阅读保持「译文 / 要点」。不改成并排的「总结」，不增加第三种阅读作为本期工作。
3. 免费引擎失败后不静默改派到另一个引擎。错误留在错误态（浮窗上的「未完成」、原因和「打开设置」）。用户自己换引擎或改设置。

6. 引擎编辑器首字母圆标是否去掉，等确认。未确认时保持圆标，不加大。
