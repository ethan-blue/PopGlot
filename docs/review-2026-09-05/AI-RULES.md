# 交给实现 AI 的统一执行规则

这是整改目标，配合 TASKS.md 执行。规则不是对当前实现的描述。用户后续明确指令优先；需要改变以下产品契约时写出原因和证据，不得无声更换。

## 1. 产品范围与不可退化项

1. 保持 Windows 桌面工具；保留 WPF、.NET、Rust domain/core/ffi、C ABI。
2. 核心入口为划词快捷键、截图快捷键、手动翻译、查词；结果含原文/译文、复制、固定、重试、展开和可选解释。
3. 不做鼠标持续监听、后台屏幕轮询、自动读取其他应用内容。只有用户明确动作才能采集选区/截图。
4. 保留四种 Provider 协议、每档案独立 Key、现有设置和配置迁移能力。不得通过删除难测功能使测试变绿。
5. 本轮不引入账号、云同步、聊天代理、插件市场、跨平台 UI、后台质量上报、自动收费 benchmark 或遥测。
6. 不以“高端/高级/像某产品”为实现标准。改动必须对应具体用户问题或已列验收项。
7. “持久迭代”指依赖有序完成任务，不是无限增加任务。完成一个闭环就进入下一项；禁止反复重画已验收 UI。

## 2. 工作区和测试安全

- 每轮读 `git status --short` 和相关 diff；不覆盖用户已有修改。不自动 commit/push/tag/release。
- 不读取真实 Key 内容，不打印配置秘密，不把系统剪贴板或用户截图作为 fixture。
- 测试用显式 `AppEnvironment/StoragePaths`（名称可调整）注入目录和依赖；仅设置 LOCALAPPDATA 不视为隔离成功。断言所有测试路径处在测试根下，所有网络发往测试服务器/假客户端，Credential Vault 为内存实现。
- 默认禁止真实公网测试；供应商 live 测试必须由负责人指定凭据、允许目标、输入与预算。测试代码存在不等于可以运行付费调用。
- 不结束用户应用进程来释放文件锁；使用另一配置/隔离产物目录，或记录确实需要用户关闭的阻塞。
- UI 回归使用虚构的 `Demo Text Service`、`demo-text-model`、`demo-vision-model` 和固定时间，不加载真实服务名、历史或凭据。
- 任何删除/迁移测试只操作自己的临时目录。不能用清空真实历史来验证按钮。

## 3. 每轮执行协议

1. **核实**：读 TASKS.md 当前任务；定位生产调用链，不只看测试替身；如果旧问题已修复，提供当前行为证据。
2. **复现**：缺陷任务先写一个旧代码会失败的反例；对不可自动化的 UI 写最小操作与观察标准。
3. **实施**：修改真实路径；只抽取确有必要的依赖；尽量保持对外 ABI 和旧数据兼容。
4. **验证**：先跑针对检查，再跑受影响项目的既有检查。涉及核心状态/协议/权限时必须跑全量必要检查。
5. **观察**：UI 查看真实渲染图；性能查看原始数据；持久化用重新加载验证；网络看发送计数而非 bool 返回值。
6. **记录**：更新 EXECUTION-LOG.md，包含编号、状态、根因、文件、用例、命令/退出码、证据路径、限制、下一项。
7. **继续**：依赖满足则自动推进；被环境阻塞的项标注 Blocked 并继续其他独立项。

状态只允许 `Todo / InProgress / ImplementedNeedsVerification / Verified / Blocked / NotApplicableWithEvidence`。没有证据不能 Verified。文件存在、构建通过、辅助函数通过、评论写着已修复，均不能单独作为最终完成证据。

遇到同一失败连续两次，先读错误和改验证假设，不能机械重跑。已通过且没有新代码/新风险的测试不重复跑。工具或权限不允许的检查写未验证，不伪造。

## 4. 网络许可与隐私

### 4.1 地址分类

| 分类 | 含义 | 仅本机模式 | 图片是否离开设备 |
|---|---|---|---|
| OnDevice | Windows OCR/本地语音等无网络组件 | 允许 | 否 |
| Loopback | 严格解析的 localhost/127.0.0.0/8/::1 | 允许 | 否（仅针对 PopGlot 的直接目标；不能保证服务自身不再转发） |
| PrivateNetwork | RFC1918、IPv6 ULA 等其他设备地址 | 默认拒绝；须独立允许局域网模型 | 是 |
| Internet/Unknown | 公网或无法证实为本机 | 拒绝 | 是/未知，不能声称否 |

“仅本机”不叫“切断一切网络”，因为回环 HTTP 仍是网络协议。UI 文案固定为：“仅使用本机 OCR、离线朗读和本机模型；不连接其他设备或互联网。”

域名/IP 分类必须使用可靠解析，测试 IPv6、凭据段、端口、大小写、非法输入、`.localhost`、私网地址、重定向。未知归保守分类。权限检查针对最终可达目标，不只检查 URL 字符串前缀。默认禁跨目标重定向；需要同源跳转时逐跳验证，不转发凭据给新 host。

### 4.2 各类发送的许可

| 操作 | 前置条件 | 不允许的隐含行为 |
|---|---|---|
| 用户配置的云端文字翻译 | 网络开 + 非仅本机 + 明确选择的档案 | 密钥失效后偷偷切免费引擎 |
| 内置公共翻译 | 上述网络条件 + FreeEngineConsent=Allowed（或明确的一次性授权） | Unset 时健康探测、打开窗口就先 ping |
| 云端截图 | 网络条件 + 图片授权 + 可用视觉配置 | OCR 不佳就无提示扩大许可 |
| 云端朗读 | 网络条件 + 独立语音选择/同意 | 把用户对翻译模型的许可当作 Microsoft 语音许可 |
| 获取模型/测试连接 | 用户主动动作 + 同目的地网络策略 | 保存自动测试、加载页面自动探测 |
| 健康检测 | 用户主动动作；复用同目标许可 | force=true 越过授权、全局离线仍发请求 |

生产发包入口需统一策略上下文与可测发送器。不能让业务代码随意 new HttpClient/ClientWebSocket 后直接发送。Rust 与 C# 有不同 transport 时共同执行同一策略用例，并在各自最后发包边界检查。

“只发送脱敏文字”不是默认承诺。应写“发送你选中或输入的文字”；token 保护用于翻译保真，不当作隐私脱敏工具。截图在内存，日志不存正文；历史是明确的本机持久化，不代表没有隐私风险。

免费引擎说明列出两个实际域名。云端语音说明列出 Microsoft 语音服务。云端语音默认关闭/使用 Windows 本地；既有用户升级不能自动新增这一目的地同意。

## 5. 翻译状态、数据和副作用

### 5.1 唯一完成判据

建议建立一份共享 `ResultEligibility`（具体命名可调整）：由规范化终态 + 完整性结果 + 非空译文计算。完成与“传输结束”分开。

| 状态 | 正文呈现 | 复制结果按钮/快捷键 | 自动复制/自动朗读/历史/收藏 |
|---|---|---|---|
| Idle | 空态 | 禁用 | 禁止 |
| Acquiring/OCR/Connecting | 阶段提示，原文保留 | 禁用 | 禁止 |
| Streaming | 可选中阅读的增量纯文本 | 应用结果动作禁用 | 禁止 |
| Finalizing | 保留已到正文，提示校验 | 禁用 | 禁止 |
| Completed 且校验通过 | 完整正文，可切 Rich Markdown | 允许 | 按用户设置执行，自动副作用至多一次 |
| Partial / FailedWithPartial / CancelledWithPartial | 保留部分正文，明确“不完整” | 应用结果动作禁用 | 禁止 |
| Failed 无正文 | 原文 + 原因 + 下一步 | 禁用 | 禁止 |

输入原文的复制功能与结果动作分开。不要全局禁用 Ctrl+C；只限制应用提供的译文快捷动作，不能阻止用户正常操作原文输入。若以后允许显式“复制部分内容”，需单独产品决定，不能本轮偷偷放开。

原文选择/截图采集取消、翻译取消、关闭浮窗、卸载页面、新 epoch 开始时，都要取消对应操作；旧回调不得改新会话或触发副作用。收到可见 Delta 后的失败不自动重发另一条线路；用户明确重试才开启新 session。

终态应包含规范化完整性信息，不能仅根据 warnings.Count 推测。现有 Rust `is_partial` 与 C# DTO 一并核对；映射丢失时修复契约而非只增加 UI 分支。

### 5.2 文本保真

- 保留 `CanonicalText/Markdown` 原始结果，不用 Pangu 或去标记结果覆盖它。
- 复制普通译文、复制 Markdown、复制代码、朗读采用各自 formatter；不同窗口共享同一 formatter。
- Markdown 先分结构，再生成视觉/复制/语音输出。代码块和行内 code 不参与自动空格、Markdown emphasis 正则、Unicode 归一化或大小写改写。
- 普通标识符 `foo_bar_baz` 和 `__init__` 也要保留；不能以“没有反引号”作为随意损坏的理由。
- 自然语言视觉间距不回写原文/译文、不进入代码复制。链接 URL 不改、路径不改；代码缩进、连续空格、空行、换行约定明确。
- 每个受保护 occurrence 恰好恢复一次。重复、缺失、未知占位符或无法判定的恢复必须不完整。相同原始单词多次出现是不同 occurrence，不可用 distinct set 替代计数。
- 所有引擎采用共同保真承诺。免费引擎如果无法可靠还原，返回明确不完整，不能悄悄关闭保护并显示绿色成功。

## 6. 产品流程默认设计

### 6.1 初次使用

继续托盘启动；首次主窗口/首次翻译显示一个内联引导，不强制系统弹窗。

文案：“选择一种翻译方式”。两个动作：“使用内置公共翻译”“添加自己的引擎”。前者展开目的地与数据说明，用户点“允许并开始”后提交当前文字；点“暂不使用”保留输入并且 0 请求。允许按钮不能藏在高级折叠中。

授权失败/保存失败时不伪装持久授权；一次性授权与永久授权状态明确分开。首次不会自动运行任何 example。可提供 `FileNotFoundError: config.json not found` 的“填入示例”操作，仅填文本，用户点翻译才发送。

### 6.2 主窗口

- 导航只有翻译、资料库，底部设置；设置不重新塞回主导航。
- 翻译正文占剩余空间；输入/译文语言工具栏共享高度和内边距。
- 以内容区可用宽度决定布局：≥720 DIP 双栏；<720 DIP 上下排列并保留输入区至少 160 DIP；不要写死基于整屏宽度。
- 宽度不足时先隐藏“自动识别源语言”等重复说明，再折叠低频操作；不缩小正文来强行塞下全部按钮。
- 顶部 Enter/Shift+Enter 提示在空间足够时显示；按钮始终可见。当前项目保留 Enter 翻译，Shift+Enter 换行，并测试中文 IME 选词回车不触发翻译。
- 输入改变不自动出网；重复提交需要明确取消/重试策略，不允许两个相同 session 同时写历史。
- 底部只显示状态、当前引擎短名和必要数据去向；完整模型 ID/域名用详情或 tooltip；绿色只代表经验证的健康/成功，不代表“有配置”。

### 6.3 翻译浮窗与查词

- 翻译浮窗默认宽 440 DIP，最小建议 360 DIP，最大不超过当前工作区；短内容高度从约 240 DIP 自适应，长内容限制为工作区高度的 75% 后滚动。具体边界需真机校验，不能绕过最小工作区约束。
- 顶栏保留固定、语言对、展开、关闭；设置、合并断行、清空等低频动作归入“更多”。只用图标的按钮必须有 tooltip 和 AutomationProperties.Name。
- 结果区核心动作：复制、朗读、收藏。原文操作不与结果操作混淆。
- 划词浮窗打开不抢走无关应用输入；用户手动编辑时再获得焦点；固定与失焦关闭关系遵循既有设置。
- 查词空状态不预留整屏白框；有结果再展开。与主工作台/浮窗共享业务服务与 formatter。
- Esc 先取消当前操作，随后关闭非固定浮窗；明确测试既有行为兼容，不把正在进行的取消变成后台继续请求。

### 6.4 设置与资料库

- UI 统一叫“翻译引擎”；内部类可保留 Provider/Profile；协议、Endpoint、SSE 不出现在普通错误主句里。
- 添加流程只要求类型/地址、Key、文字模型；图片独立可选；路径、头、TLS 等归高级。
- Key 留空表示保留已有 Key；明确“清除密钥”独立动作；验证连接只使用内存草稿。
- 保存写盘，设置默认切路由；二者不同。保存按钮常驻底部，默认切换显示即时生效；脏草稿离开提供内联保存/放弃/继续编辑。
- 资料库区分“历史（自动）”和“收藏（主动）”。收藏身份至少考虑词面+源/目标语言；代码词面是否区分大小写必须明确，默认不合并不同代码标识符。
- 保存失败显示“未保存到本机，请重试”，不显示成功星标。清空需要明确确认，删除可提供撤销；失败保留数据及选择项。

- DangerButton 不把亮红底配白字当万能方案；暗色危险操作默认 DangerText+Soft；hover/pressed 独立验证。
- 高对比模式优先于用户自选深浅，映射 SystemColors；系统变化时刷新已开窗口与已渲染 FlowDocument。高对比不是第三套随意品牌色。
- 禁止页面硬编码业务颜色；必要的品牌资产颜色、截图遮罩等例外集中声明。白色也使用语义 token。

### 7.2 字体、间距、尺寸

| 项目 | 目标 |
|---|---|
| 单位 | WPF 尺寸为 DIP；像素只用于截图/显示器边界 |
| UI 字体 | Segoe UI Variable Text, Segoe UI, Microsoft YaHei UI |
| 代码字体 | Cascadia Mono, Consolas, Courier New |
| 页标题 | 18 DIP / SemiBold；工作台紧凑标题可用15，定义独立 token |
| 分组/设置标签 | 13 DIP / Medium 或 SemiBold |
| 翻译正文 | 15 DIP，建议行高22；用户可调14/15/16/18 |
| 说明 | 12 DIP，建议行高18 |
| 元数据 | 11 DIP，仅用于非关键次要信息 |
| 代码 | 13 DIP，等宽；禁止自动 Pangu；允许水平滚动/可选换行 |
| 控件高度 | 普通输入/按钮至少32 DIP，设置主按钮36 DIP |
| 图标按钮 | 默认32×32 DIP，极紧凑可28×28，图形14—16 DIP |
| 圆角 | 控件6、卡片10、浮窗12 DIP；主工作台单阅读面可4 |
| 间距集合 | 4/8/12/16/24/32 DIP；边框1、焦点环2 DIP |

不使用任意 14/18/28 间距遍布页面；旧值不是必须一次全改，受影响组件先统一。布局用 Grid 的 Auto/* 与明确约束，不用负 Margin 掩盖重叠。

流式和终态共用正文尺寸/行高，保留滚动位置；用户向上阅读后不强制 ScrollToEnd；代码块出现可以自然增加高度，但不得导致字体整体缩小。禁止大面积透明窗口、文字缩放动画和长渐变遮罩。微反馈建议120ms；系统减少动画偏好下禁用。

### 7.3 可访问性与视觉验收

- Tab 顺序跟阅读顺序；键盘焦点可见；Esc/Enter/空格/方向键符合对应控件语义。
- 图标按钮具有可读名称；状态变化使用合适的 automation 通知，流式不逐字朗读状态以免刷屏。
- 检查深/浅/系统高对比；100/125/150/200% 缩放；主窗960×640 DIP、最小可用宽、紧凑编辑器、长模型名和长错误。
- “逻辑尺寸960 DIP、缩放2”应生成1920px宽图；不能一边除2一边再乘2。若测试固定物理视口，则先换算 DIP，位图仍保持该固定物理尺寸。两种测试分别命名。
- 离屏渲染不证明 WindowChrome、真正焦点、混合显示器位置；这些保留真机测试项。
- 自动视觉检查覆盖有效颜色、控件边界和合理内容占比；图片基线仅在人工看过差异后更新。不能通过更新 golden image 接受明显重叠。

## 8. 资源、错误、持久化和算法边界

- 每个活动会话、窗口、CancellationTokenSource、native buffer、位图、流、音频文件、计时器、事件订阅均有明确所有者和释放位置。
- TTS 停止/替换取消合成与播放；过时代际结果不播放且清理临时文件。语音选用明确语言对，字符脚本只是后备，emoji 不代表德语。
- 网络分片按协议消息处理；SSE 保留 UTF-8 边界、随机 trailer 跨 chunk、错误/截断终态；WebSocket 按 EndOfMessage 组装后解析，有单消息与音频总大小限制。
- 所有外部读取在分配前或累积过程中执行上限；有 Content-Length 不能代替累计限制。免费翻译建议响应4MiB、一次操作总时限12s、单条源5000字符先保持；详细调整需记录。
- 词库建议最大10000条、单条源/译各8000字符、文件32MiB；超限明确拒绝/引导导出，不静默删旧收藏。历史现有200条/90天/4MiB先保留。
- 写盘采用先准备新快照、原子替换成功后提交内存；失败返回结构化结果；不能 catch 空吞。清除和删除也要处理失败。
- 保存、历史和 UI 错误通过明确 Result 表达；异常不靠中文 Contains 决定主要业务分支。
- 日志默认仅错误类别、操作阶段、request ID、允许的计时/大小；不记 Key、鉴权头、全文/截图、含 query 的 URL。建议单文件1MiB、总10MiB、保留7天；启动/写入时轮转。
- 文本长度限制需分清 UTF-8 字节、UTF-16 char 和用户可见字符。错误提示写出该引擎实际限制，不混用。
- 任何算法复杂度声明要与输入规模对应。追加 k 字节不是 O(1)，使用锁不是无锁。先记录基线再优化。

## 9. 性能与质量验收

### 9.1 指标定义

必须同时记录以下时间点：用户动作、采集完成、OCR完成、发送开始、首个网络正文到达、首个可展示 delta、首帧正文显示、最终校验完成、取消触发、发送任务退出。不要把“API首包”“首字回调”“屏幕看到文字”都叫 TTFT。

| 指标 | 目标预算 | 验证条件 |
|---|---|---|
| 独立应用启动至托盘可用 | P50≤600ms，P95≤1200ms | Release，明确冷/暖缓存，不用测试宿主 |
| 热键至选区显示 | P95≤150ms | 真实消息/显示路径，mock只能标内部阶段 |
| 截图确认处理 | P95≤100ms | 明确是否包含PNG编码 |
| 1080p OCR | P50≤500ms，P95≤1200ms | 固定fixture、语言包和机器 |
| Core增量处理额外开销 | P95≤20ms | mock网络到可展示delta，不含供应商延迟 |
| 首delta到UI呈现 | 建议P95≤50ms | 明确包含Dispatcher/40ms泵；不能声称20ms |
| 空闲应用工作集 | 目标≤80MiB，硬预算≤120MiB | 独立Release，稳定30秒后采样，非测试进程 |
| 空闲CPU | 建议归一化总CPU均值≤0.5% | 稳定60秒采样，报告机器核心数及计算方法 |
| 取消 | UI立即反馈；建议请求任务退出P95≤200ms | 正在进行的延迟mock请求，不是无活动取消 |

启动至少30个进程样本；交互/mock场景至少100次；保存原始样本及P50/P95算法、硬件、OS、运行时、构建与提交。环境不可测就写未测；单次快照不称P95。

### 9.2 翻译质量

固定60条合成输入，覆盖英语→中文、中文→英语、混排及其他代表语种。所有关键 code token 完整率100%是硬门槛。语义/术语/遗漏/无依据扩写分项评估，保留可复核参考与允许多种正确译法的 rubric。不能拿字符串完全相等当语义质量，也不能用另一个模型一句“很好”作为唯一评判。

模型推荐不得捏造上下文窗口、价格、速度或视觉能力。启发式只写“根据名称推测”，实测写样本/时间/端点匹配；无数据就 Unknown。目录健康不能阻止保存或使用用户自填模型。

## 10. 最终完成标准

一项任务完成必须同时满足：生产行为改变、旧错误回归被捕获、必要测试实际通过、用户流程无已知退化、文档/迁移同步、证据可定位。

整轮完成必须：T01—T03 无未解决阻断项；其他任务逐项有状态；新配置不扩大权限；真实用户数据未用作测试；UI 对比度不是仅 token 推断；性能没用伪测量；所有未运行场景明确标注。

输出模板：

```text
任务：Txx（状态）
原问题：具体触发条件和错误结果
实现：文件/方法、改变后的行为
验证：命令、退出码、断言、截图/数据路径
兼容性：旧配置/现有数据/取消行为
未验证：真实设备/供应商等具体条件
下一项：编号、依赖、第一处代码入口
```

不要输出“全面优化完成，体验大幅提升”一类无证据结论。确实完成可简洁陈述；未完成不要用换词隐藏。
