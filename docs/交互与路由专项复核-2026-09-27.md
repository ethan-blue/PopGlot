## 根因与修改

### 1. 开关焦点形状

- 根因：`ToggleSwitch` 和 `SwitchCheckBox` 复用了矩形控件的 `FocusRing`，其半径、线宽和 22/24 DIP 胶囊轨道不一致，选中后像额外的模糊光圈。
- 修改：`apps/PopGlot.Windows/Themes/Controls.xaml` 新增 `SwitchFocusRing`，采用 1 DIP 清晰描边和胶囊圆角，并用于两种开关。
- 行为：鼠标选中态只保留轨道、旋钮和边框；键盘导航仍能看到与轨道同形的焦点标识。

### 2. 引擎菜单信息密度

- 根因：每项把 `名称 · 模型 ID` 常驻显示，并为模型 ID 预留 164 DIP；弹层固定 248 DIP。
- 修改：`apps/PopGlot.Windows/MainWindow.xaml.cs` 可见文字只显示名称，模型详情移到 Tooltip/AutomationProperties；内容宽度改为 124 DIP，弹层改为 208 DIP。
- 行为：长模型名不再把弹层撑宽；读屏和悬停仍可获得完整模型信息。

### 3. 语言方向与请求生命周期

- 根因：工作台允许请求进行中修改标题语言；浮窗选择或交换语言会立即取消旧操作并重新请求，和工作台“只改方向”的行为不一致，也可能产生未明确触发的付费请求。
- 修改：
  - `apps/PopGlot.Windows/Sections/TranslateSection.xaml(.cs)`：请求期间锁定方向控件；普通选语言清除旧结果；交换按钮明确为本地操作。
  - `apps/PopGlot.Windows/TranslationPanelWindow.xaml(.cs)`：选语言/交换不再自动请求；请求期间锁定方向控件；状态提示按 Enter 翻译。
- 行为：只有翻译动作会创建请求。切换方向不会改写在途 route，也不会自动消耗模型额度。

### 4. 要点能力与缓存耗时

- 根因：能力层已经能判断免费线路不支持生成任务，但 UI 只改 Tooltip，没有禁用控件；要点缓存只保存正文和说明，切回缓存时人为构造 `ElapsedMs=0`、空引擎。
- 修改：
  - `TranslateSection.xaml.cs` 与 `TranslationPanelWindow.xaml.cs`：只有 `Available/Unknown` 模型线路可以点击要点；能力失效时取消要点并回到译文。
  - `ReadingModeState.cs` 与 `SummaryLifecycleCoordinator.cs`：缓存同时保存原始耗时和引擎标签。
  - `TranslationCoordinator.cs`：摘要快照执行前比较 `ProfileManager.Revision`，拒绝跨配置执行。
  - `TranslationModels.cs`：亚 100 ms 统一显示“< 0.1 秒”。
- 行为：公共翻译仅能翻译；要点只走模型线路；缓存命中不会伪装成一次 0 秒模型请求。

### 5. SDK、取消、并发与长期运行

- genai 固定为 0.6.5，并由 `vendor/genai` 提供受审快照；`provider_sdk.rs` 显式映射 OpenAI Chat、OpenAI Responses、Anthropic Messages、Gemini 四种协议，不按模型名猜 route。
- 产品自己的传输层继续提供：共享连接池、5 秒连接超时、非流式 120 秒总超时、流式 120 秒空闲/600 秒总超时、有限重试、取消 token、响应大小上限和同源跳转策略。
- provider HTTP 回归覆盖慢首 token、中途取消、取消后无后续 delta、断流、错误帧、超时、重试和四协议请求体。
- 结论：SDK 边界与取消契约具备本地回归证据；“支持高并发”仍取决于用户配置服务的额度、速率限制和模型吞吐，桌面 UI 测试不能替第三方给出 SLA。

### 6. 译文与要点的 Markdown 契约

- 现状：工作台与浮窗的最终译文、要点都已调用 `MarkdownPresenter.RenderToFlowDocument`，支持标题、自然段、列表、引用、表格、HTTP/HTTPS 链接、行内代码、代码块和粗体；流式进行中使用纯文本层，完成后切换富文本层。
- 根因：翻译任务已经允许结构化 Markdown 和适度粗体，但要点/解释任务只要求项目符号，没有明确规定 Markdown 层级、重点强调和代码/链接保真；流式翻译提示词又把“Markdown 结构”和可翻译文字一起写成“逐字节保留”，语义有冲突。
- 修改：`crates/popglot-core/src/provider.rs` 要求要点按内容复杂度返回段落或 3–6 条 Markdown 项目，可给每项使用一个简短粗体引导词，但禁止凭空制造重要性；解释任务采用相同的克制规则。翻译协议改为保留 Markdown 定界符和层级，同时翻译标题、列表、表格单元格和链接标签，只把 URL、代码、命令、路径、标识符及占位符视为逐字节保护内容。
- 行为：模型返回的 `**重点**`、列表、表格和代码会进入终态富文本显示；不会在客户端按关键词二次加粗，也不会静默增加一次模型请求。复制继续输出适合普通剪贴板的纯文本，保留编号、项目符号、缩进和单元格结构；朗读移除 Markdown 标记。
- 边界：模型是否实际采用粗体仍受模型遵循度影响；没有真实付费请求，本轮只验证了提示词、模拟协议响应解析和现有渲染链路。

## 内置公共线路合规复核

Google 官方 Cloud Translation 要求启用项目、计费和认证；Basic v2 支持 API key，Advanced v3 使用 ADC/IAM。官方还要求应用内说明和相应归因。当前内置 Google 路线没有走这些公开 API，也没有对应项目、认证、计费或归因流程，因此不能把它认定为 Google Cloud Translation 的合规集成，也不能承诺批量或长期使用。

MyMemory 官方规格把 `q` 限制为最多 500 字节。本轮已在本地按 UTF-8 字节数拦截，超限不消耗出网授权、不发送请求。其匿名服务仍可能限流、变更额度或不可用。
