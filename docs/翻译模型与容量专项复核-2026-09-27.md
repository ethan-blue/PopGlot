# 翻译模型与容量专项复核（2026-09-27）

## 结论摘要

- 文字翻译与截图翻译分别读取文字模型/端点和图片模型/端点。协议由用户配置显式决定，不按模型名称切换协议。
- “1000 字符”不是当前限制。当前为每段最多 **800 个 Unicode 字符**、每次会话最多 **8 段**；不可安全切分的超长代码块会在发送前拒绝。
- 模型输出上限按任务设置：普通翻译为 `2 × 源字符数 + 256`，限制在 **384–1200 token**；整理要点为 **700 token**；解释为 **900 token**；截图翻译为 **1200 token**。
- 单个 HTTP 请求体最大 **12 MiB**，单个响应流最大 **4 MiB**。本次补上了多段文字翻译的整会话 **4 MiB UTF-8** 总上限，防止异常服务把 4 MiB 按最多 8 段累加。
- C# 流缓冲还设有 **1,000,000 个 UTF-16 code unit** 的字符保险上限；正常请求会先受到 1200 token 的模型输出上限约束。
- 截图最小边长 **6 物理像素**，最大 **1600 万物理像素**，PNG 编码后最大 **8 MiB**。FFI 的 Base64 输入保护为 **12 MiB**。
- Markdown 加粗链路已存在：提示词允许适度 `**加粗**`，协议解析保留 Markdown，WPF 终态以 `SemiBold` 渲染；历史保存原 Markdown，纯文本复制去掉标记并保留文字。真实模型是否稳定遵守、当前运行实例中的实际观感仍需真机验证。

### 关于“1000 字符”

当前实现不是 1000 字符，而是 800 字符/段。这里按 Unicode 字符计数，不按 UTF-8 字节计数。800 字符配 1200 token 是当前延迟和输出容量策略，并不等于所有语言方向都能得到质量保证。中文翻译成较长英文、同时要求解释时仍可能触及 1200 token；真实服务质量与截断率没有付费实测证据。提高 token 上限会改变费用和延迟，本轮未擅自调整。

## 截图链路

1. 选区使用物理像素；进程为 Per Monitor DPI aware，截图不由系统二次缩放。
2. 面积超过 1600 万像素时，在创建位图前拒绝，避免约 64 MiB 以上的 32bpp 原始位图继续增长。
3. 生成 PNG 后检查 8 MiB 上限；高噪声画面即使像素数合规，也可能因 PNG 太大而要求缩小选区。
4. 8 MiB 原图 Base64 后约 10.67 MiB；四种协议的实际 JSON 序列化均通过 12 MiB 请求体预算回归。
5. 截图字节只在本次请求内使用，暂存会话不保存图片引用。

## 本次修改

### 多段输出总量没有统一上限

- 根因：Rust transport 和 `TranslationStreamBuffer` 只限制单请求 4 MiB；`TranslationCoordinator` 使用 `StringBuilder` 合并最多 8 段时没有整会话预算。
- 修改：新增 `MaxTextSessionOutputBytes = 4 MiB`；每一段只获得剩余响应预算；达到上限后不发下一段。异常执行器绕过流缓冲限制时，终态再次按 UTF-8 字节检查。
- 行为：保留已完整完成的前缀，结果标为 Partial，显示明确警告，不写历史，也不触发完整结果的自动复制、朗读或收藏副作用。
- 同时修复：分段请求取消或失败时，保留当前缓冲区已经返回的受限片段，而不只保留前几段。
