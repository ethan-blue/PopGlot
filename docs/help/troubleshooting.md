# 常见故障与自愈诊断 (Troubleshooting)

PopGlot 遵循「错误具有修复路径，绝不陷入死胡同」的自愈型 UI 原则。当遇到网络中断、授权过期或系统权限问题时，界面会明确展示原因并提供针对性的解决入口。

本文档汇总日常使用中最常见的故障现象与应对指南。

---

## 1. 提示「尚未配置翻译引擎」/「未配置引擎」

### 现象表现
- 主工作台右侧展示引导卡片：`尚未配置翻译引擎`；
- 极速查词底栏或划词浮窗显示错误卡片，提示需要配置可用引擎。

### 原因排查
- 您尚未在「设置 → 翻译引擎」中添加任何自定义大模型；
- 或尚未开启「内置公共翻译」后备服务。

### 解决路径
1. **方案 A（连接个人大模型，推荐）**：
   - 直接点击错误卡片中的**「添加翻译引擎」**或**「打开设置」**按钮；
   - 系统将自动弹出设置窗口并定位至添加引擎界面，填入 API Key 后保存即可恢复正常。
2. **方案 B（开启内置公共翻译）**：
   - 在主工作台空态卡片中点击**「使用内置公共翻译」**；
   - 确认授权协议后即可立即开始无 Key 免费翻译。

---

## 2. 提示「鉴权失败 (HTTP 401)」/「Invalid API Key」

### 现象表现
- 浮窗结果显示红色警示：`连接失败 (401 鉴权失败)`；
- 点击「获取模型」或「验证连接」时提示 API Key 错误。

### 原因排查
- 服务商控制台重新生成了密钥，本地保存的旧 Key 已失效；
- 复制 API Key 时不小心夹带了多余的前导或尾随空格；
- Base URL 与服务商不匹配（例如将 DeepSeek 的 Key 发送给了 OpenAI 的端点）。

### 解决路径
1. 前往「设置 → 翻译引擎」，在左侧列表选中报错的引擎；
2. 点击 API Key 输入框右侧的**「清除」**按钮；
3. 从服务商后台重新复制最新的 API Key，粘贴入密码框；
4. 点击「验证连接」确认通过后，点击底栏「保存」。

---

## 3. 提示「请求被限流 (HTTP 429)」/「接口并发超限」

### 现象表现
- 翻译返回错误信息：`免费翻译接口刚刚被限流（HTTP 429），一分钟内暂不自动重试`；
- 或者商业大模型返回 `Rate limit reached`。

### 原因排查
- **公共翻译服务**：Google 公共端点对单一公网 IP 存在短时请求频次保护，短时间内大量快速选词可能触发短时冷却；
- **商业大模型**：您的 API 账户达到了并发请求上限（RPM）或按天额度上限（TPM），或者账户余额不足。

### 解决路径
- **对于公共翻译**：PopGlot 会自动进入 1 分钟安全冷却保护，通常等待几分钟后即可自动解除；
- **对于商业模型**：
  1. 前往服务商控制台检查账户配额与账单余额；
  2. 推荐在「设置 → 翻译引擎」中配置一个备用模型引擎，当主引擎限流时可快速切换。

---

## 4. 提示「网络访问未启用」/「安全离线模式生效中」

### 现象表现
- 所有划词与截图翻译均被直接拦截，状态显示为：`网络访问未启用` 或 `安全离线模式已开启`。

### 原因排查
- 在「设置 → 隐私与数据」中开启了「安全离线模式」；
- 或者关闭了「启用大模型网络翻译」总开关。

### 解决路径
1. 打开「设置 → 隐私与数据」；
2. 找到**「安全离线模式」**选项，将其切换为关闭状态（圆点居左）；
3. 确保**「启用大模型网络翻译」**处于开启状态；
4. 切换后即刻生效，无需重启应用。

---

## 5. 提示「生词本文件损坏，已处于只读保护」

### 现象表现
- 打开「资料库」查看生词本时，界面顶部出现黄色警告卡片：
  `生词本文件损坏，当前处于只读保护状态。未保存任何新数据。`
- 收藏新词功能临时被禁用。

### 原因排查（C02 契约安全保护）
- 计算机在先前写入磁盘时遭遇了非正常断电、蓝屏或磁盘强制拔出，导致 `%LOCALAPPDATA%\PopGlot\vocabulary.json` 出现了未写全的残损字节；
- 为了绝对防止软件盲目覆盖而导致用户多年积累的生词资产全盘丢失，PopGlot 会**立刻触发只读保护机制**。

### 解决路径
1. 观察警告卡片右侧提供的**「重试加载」**主操作按钮，点击尝试二次校验解析；
2. 若重试后仍未恢复，可在文件资源管理器中打开 `%LOCALAPPDATA%\PopGlot\`；
3. 将损坏的 `vocabulary.json` 备份为 `vocabulary.json.bak`，使用文本编辑器修复尾部缺失的花括号 `}`；
4. 重启 PopGlot 后，生词本将自动恢复正常读写。

## 6. 开机启动项被系统禁用（Windows 任务管理器拦截）

### 现象表现
- 在「设置 → 通用」中勾选「开机自动启动」后，下方提示：
  `开机启动已被 Windows 任务管理器禁用，PopGlot 无法单方面强制开启`；
- 旁边出现「重新启用」按钮。

### 原因排查
- 您先前在 Windows 任务管理器的「启动应用」标签页中，曾手动将 PopGlot 的状态设为了「已禁用」；
- Windows 操作系统的安全设计（`StartupApproved` 注册表分支）赋予了任务管理器高于普通软件的绝对优先权，普通软件无法也不应当在后台静默覆写系统的禁用决定。

### 解决路径
1. **方法 A（软件内一键申请）**：
   - 点击设置行中的**「重新启用」**按钮；PopGlot 将尝试向系统注册表写入合规的重新启用申请；
2. **方法 B（Windows 原生设置）**：
   - 按下键盘快捷键 `Ctrl + Shift + Esc` 打开「任务管理器」；
   - 切换到「启动」或「启动应用」选项卡；
   - 在列表中找到 `PopGlot`，鼠标右键点击并选择**「启用」**；
   - 回到 PopGlot 设置页，状态将自动同步为正常开启。

---

## 7. 遇到其他未知异常

若遇到界面无响应或未预期的闪退：
1. 本地日志位于 `%LOCALAPPDATA%\PopGlot\diagnostics\` 目录下；
2. 日志已执行严格隐私脱敏（绝无任何您的翻译文本与密钥）；
3. 可将该日志文件附在 GitHub Issues 中反馈给开发团队。
