## A. 优先修复：内容与数据（P1）

### F01 复制会改写行内代码中的 Markdown 链接【已复现】

- 位置：`apps/PopGlot.Windows/Services/MarkdownPresenter.cs`，`ToPlainText`，约 237–248 行。
- 输入行内代码：`` `[x](y)` ``。实际纯文本复制：`x (y)`；应为 `[x](y)`。
- 根因：链接正则替换在行内代码保护之前执行，改写了代码内容。三个翻译入口均使用此方法，不只是一个页面。
- 要求：先分出代码与自然文本，链接转换只作用于自然文本；避免全字符串预处理。
- 验收：行内代码包含链接、反斜杠、括号及多个反引号；复制代码内容逐字一致，围栏代码原有保真测试不退化。

### F02 含括号的链接被截断，点击错误地址【已复现】

- 位置：同文件 `AppendFormattedSpans`，约 563、585 行。
- 输入 `[文档](https://example.com/a_(b))`。
- 实际显示 `文档)`；实际 NavigateUri 为 `https://example.com/a_(b`，丢失闭合括号。
- 要求：用能识别平衡括号、转义和代码边界的解析方式；继续保持 http/https 白名单，不扩大可执行 URI 范围。
- 验收：普通 URL、带括号路径、转义括号、标题、非 http 协议；可见标签与实际目标均正确。

### F03 编号列表复制后丢失序号【已复现】

- 位置：同文件 `ToPlainText` 的编号/无序列表分支，约 214–231 行。
- 输入 `1. first\n2. second`，复制变成 `first\nsecond`。无序列表标记也被剥离，嵌套层级无法保留。
- 要求：明确复制与朗读是不同用途；“复制译文”保留有意义的序号、列表与缩进，不能为了朗读去标记而破坏复制内容。
- 验收：从 3 开始的编号、跳号、嵌套列表、多段步骤在工作台、浮窗、查词及导出保持语义结构。

### F04 撤销票全局只有一张，第二次操作使第一次提前失效【内存复现 + 代码确认】

- 位置：`Services/LibraryUndoJournal.cs` 的 `_ticket`；`Sections/DataSection.xaml.cs` 的两个撤销按钮。
- 复现：清空历史后，在 20 秒内清空生词本，再点历史撤销。第二次 Offer 覆盖第一张票，第一张未到期就无法 Take。
- 内存测试已确认连续 Offer 后第一张票立即取不到；设置页却分别保留两个“撤销”按钮，没有同步提示替换。
- 要求：至少按操作 ID 保留有限数量的未过期撤销记录；或明确采用单步撤销并同步所有页面，但不能显示仍有效的假按钮。推荐前者。
- 验收：跨历史/生词本/设置页连续删除清空、逆序撤销、到期、失败重试、重启边界；不得覆盖后来新增或修改的记录。

### F05 历史容量不足时只恢复部分，却提示全部成功【代码确认】

- 位置：`HistoryStore.cs:425` 的 `InsertMissing`、约 449 行容量分支；`Sections/LibrarySection.xaml.cs:673`；`Sections/DataSection.xaml.cs:109`。
- 复现路径：清空 200 条历史 → 新增 1 条 → 撤销。容量限制使最多恢复 199 条，只要 inserted > 0，调用方就显示恢复成功；整张票此前已被 Take 消耗，剩余条目失去撤销机会。
- 要求：返回恢复数量、跳过原因及剩余条目；部分恢复必须明确反馈，不能丢掉剩余可恢复数据或挤掉新数据。
- 验收：满容量、部分容量、全部条目已存在、写入失败；成功/部分成功/无须恢复/失败四种结果准确。

### F06 “清空历史”同时删除暂存会话，但撤销只恢复历史【代码确认】

- 位置：`Sections/DataSection.xaml:34–47`；`DataSection.xaml.cs:69` 的 `App.SharedSessionStore.Clear()`；`UndoHistory_Click`。
- 用户点击的标签与提示是清空翻译历史，可短时撤销；实际额外删除暂存会话，撤销票不包含会话。
- 影响：用户以为撤销能恢复这次操作，未完成草稿/暂存内容实际上无法恢复。
- 要求：将“清空暂存”拆为明确操作，或事前准确说明范围及不可恢复部分。不要未经设计将会话隐式加入持久化备份。
- 验收：创建未完成暂存 → 清空历史 → 撤销，确认行为与操作前的说明一致。

## B. 阅读与交互（P2）

### F07 Markdown 硬换行的反斜杠残留【已复现】

- 位置：`MarkdownPresenter.cs:519` 硬换行分支与 `AppendFormattedSpans`。
- 输入第一行末尾单个反斜杠后换行，渲染确实产生换行，但反斜杠仍显示并进入纯文本复制。
- 要求：识别语法标记与字面反斜杠，正确处理奇偶转义；仅消费换行语法，不破坏代码及路径。
- 验收：单/双反斜杠、行尾双空格、行内/围栏代码、末行无后继行。显示与复制规则一致。

### F08 表格显示、复制和 Markdown 支持范围仍不一致【已复现 + 代码确认】

- 位置：同文件 `IsTableLine`、`CreateTableBlock`、`ToPlainText`。
- 表头 `**名称**` 使用 TextBlock.Text 直接输出，正文单元格却走格式解析，表头样式标记会原样露出。
- `ToPlainText` 不识别表格结构，分隔行 `| --- | --- |` 和转义符残留在复制文本。整表使用 BlockUIContainer；实际 TextRange 提取只有空白，不包含表格单元格文本，选择复制链路存在缺口。
- 只接受首尾均有 `|` 的表格，不支持常见的省略外侧竖线写法。当前只能称 Markdown 子集，不能称完整 GFM。
- 要求：统一结构解析；定义复制表格为可读纯文本/TSV或保留 Markdown 的明确策略；明确支持范围，必要时采用成熟解析库而非继续堆正则。
- 验收：表头强调、内联代码/链接、转义竖线、空单元格、无外侧竖线、窄窗、多行内容、全文复制与选择复制。

### F09 删除翻译规则的二次确认会把四字文本塞进图标按钮【代码确认，视觉待复现】

- 列表按钮固定宽 32 DIP，首次点击把 Content 改成“确认删除”，未调整宽度，四字文本会超出图标按钮的设计尺寸；Tooltip 仍是 3 秒二次确认，和资料库单击删除/撤销不一致。
- 要求：采用内联确认区或统一的删除后撤销，不往固定尺寸图标按钮塞长文；同步 AutomationProperties.Name。
- 验收：列表/编辑器两入口、键盘、读屏、125%–200% DPI；无溢出，确认状态清楚。

### F10 设置页撤销按钮不会随时间自动失效隐藏【代码确认】

### F12 圆角外框与内部方形背景不一致，重点检查翻译规则页【用户反馈，待定位复现】

- 用户补充：部分控件外层是圆角，后面的背景或内部区域却是方框；翻译规则页尤其明显。本轮记录该反馈，不声称已定位到某一模板或已修复。
- 重点位置：`Sections/PromptSection.xaml` 的规则选项、规则列表卡片与编辑分组；`Themes/Controls.xaml` 的按钮/输入框/列表项模板。同步检查其他页面复用这些模板的控件。
- 复现要求：分别截图普通、悬停、按下、选中、键盘焦点、禁用状态，并检查深浅主题及不同 DPI。圈出具体控件、外层圆角和内层方形背景，不仅看默认静态截图。
- 排查方向：父 Border 的 CornerRadius 不会自动把所有子内容裁成圆角；检查子 Grid/Border 背景、模板状态层、焦点装饰层、滚动内容是否覆盖圆角或露出方形底色，以及嵌套圆角与内边距是否协调。这些是排查方向，不是已经确认的根因。
- 修改要求：同一控件的外框、背景和交互状态层使用一致的形状与圆角资源。需要裁切时使用与实际尺寸匹配的圆角裁切或调整模板层级，不要只设置 `ClipToBounds=True` 就认为完成圆角裁切。不要靠加大外边距遮盖，也不要把所有控件强行改成圆角；无意采用圆角的区域可以统一为直角。
- 验收：翻译规则列表、选项切换、添加/编辑页在所有状态均无方角背景露出、边框重叠或色块错位；焦点环、文字、下拉弹层和阴影不被误裁切。附同一控件修复前后截图，并回归复用模板的其他页面。
