# PopGlot 多角色产品审查与 AI 修改规格

日期：2026-09-26。审查基线：`419db04b96377a5de36bdb0ab76662c79dfa1f8a`。开始时工作区干净。

本文供接手的 AI 实施与验收使用。本轮仅审阅本地代码与文档、编写交接文件，未修改产品代码，未运行 GUI、测试或真实服务，未核实远端发布状态。角色分析是同一次审查的不同视角，不代表独立专家或多个 AI 已完成评审。

## 1. 产品判断

PopGlot 的核心价值明确：用户不离开当前工作上下文，就能理解技术文字和截图。当前不足不在于功能数量，而在于首次成功的门槛、多个入口的状态一致性、翻译质量证据与发布可信度。建议先稳定“选中 → 翻译 → 理解 → 复制 → 回到工作”，再扩展学习、文件或跨平台功能。

已有能力应保留：WPF / Rust 分层、多协议引擎、离线策略、凭据管理、剪贴板序列保护、部分结果与终态区分、译文与要点分离、主题与窄窗布局、历史和生词本损坏保护。不要把这些已存在的能力当成待从零建设的功能。

证据分级：

- **代码确认**：当前源码可直接确认的行为或矛盾；仍不等于真机复现。
- **待验证风险**：有具体触发场景，但本轮未证实运行结果。
- **产品建议**：为改善体验提出的新行为，不伪装成缺陷。
- 验收只使用“通过 / 不通过 / 未验证”，并附版本、环境与证据；历史 DONE 标签不算当前通过。

优先级：P0 为隐私、数据损坏或内容保真阻断；P1 为核心流程正确性与可用性；P2 为效率、质量体系与维护性。本轮没有真机确认的 P0 漏洞，P0 测试要求不能写成已发现漏洞。

## 3. AI 执行任务

### R01 · P1 · 修复要点缓存及异步结果归属

入口：`apps/PopGlot.Windows/Services/ReadingModeState.cs` 的 `HasSummary` / `RememberSummary`；`Sections/TranslateSection.xaml.cs` 的 `ShowSummary_Click`（约 595、633 行）；`TranslationPanelWindow.xaml.cs` 对应调用（约 453、487 行）；`Services/TranslationCoordinator.cs` 的 `RunTextTaskAsync`。

现状：缓存键只有原文。工作台请求实际传入源语言、目标语言；请求返回时 `sameSource` 也只比较原文。因此改变目标语言既不使已有缓存失效，也不能阻止正在执行的旧语言结果被展示为当前结果。

复现候选：同一原文生成中文要点 → 切回译文 → 改目标语言为日语 → 点击要点。另测中文请求进行中改目标语言，等中文响应返回。当前代码路径应由可控执行器验证，再做真机确认。

修改要求：

1. 创建不可变的要点请求身份，至少包含原文、源语言、目标语言、任务类型、实际引擎/模型与影响输出的配置版本。仅当风格实际进入要点请求时才纳入风格修订，不假设译文风格已经作用于要点。
2. 缓存与完成回调使用同一身份；身份应在路由解析时与请求一起快照，不能 UI 读一次配置、服务发送时又读另一个版本。
3. 为要点请求引入递增 generation 或等价机制；用户改变输入/语言/有效路由时，旧回调不得覆盖当前界面。旧结果可作为旧身份缓存保留。
4. 工作台与浮窗采用同一规则。切换视图本身不重复发请求；重新生成是明确动作。取消/失败不写入成功缓存。

验收：同身份切换两次只发送一次；换目标语言必生成新语言；同原文换引擎不得冒充新引擎结果；旧请求晚到不能覆盖新请求；取消后晚到无副作用；切回译文保留原结果。用计数 fake executor 和可控异步完成顺序测试，补一条真实桌面录像。

失败处理：保留译文；要点区域显示可重试错误；不得通过清空所有状态掩盖身份问题。依赖：无。

### R02 · P1 · 缩短首次成功路径

入口：`App.xaml.cs` 启动/托盘逻辑、`Sections/TranslateSection.xaml(.cs)`、`Sections/PrivacySection.xaml(.cs)`、`Services/OutboundPolicy.cs`。

产品建议：保留正常启动进托盘约定。首次打开工作台或首次请求因未配置被阻止时，在原位置给出三个明确出口：“允许公共翻译”“添加引擎”“查看离线用法”。不新增强制弹窗，不自动外发测试文字。

允许公共翻译必须在用户看到选中接收方和发送内容后明确点击；复用现有授权策略，不在 UI 另造授权布尔值。授权成功后可继续用户刚才发起的同一请求；取消或保存失败时保留原文。后台自启不得自动打开引导。

验收：全新隔离配置下，从首次打开工作台到具备可翻译状态最多两次必要动作（不含输入文字和个人引擎配置）；授权前 sender 调用为零；拒绝后能切到本机模型；重启不重复干扰已配置用户。实际耗时与点击数记录为观察值，不能捏造转化率。依赖 R06 的准确披露。

### R03 · P1 · 让能力差异提前可见

入口：`Services/TranslationCoordinator.cs:RunTextTaskAsync`、工作台/浮窗要点入口、`Services/EngineWording.cs`、`Sections/ServicesSection.xaml(.cs)`。

现状：无有效模型路线时服务明确抛出“免费引擎不能整理要点”。先核对 UI 当前是否已经解释该限制，避免重复加提示。

修改要求：从实际路由派生统一能力状态：可用、需配置、不支持、未知。要点不可用时显示一句原因和“添加引擎”入口；不要让用户必须先遭遇一次异常。未知能力不能硬判不支持，连接测试失败也不能阻止保存。要点为独立模型请求，首次使用处简短说明可能产生额外服务费用，不编造价格或 token 成本。

验收：免费线路、本机模型、有效远程路线、无凭据、未知模型五种状态；三个翻译入口使用一致词汇；切引擎实时更新；导航到设置后返回保留输入。依赖 R02 可共享导航，但服务限制不可移除。

### R04 · P1 · 收敛核心交互与无障碍验收

入口：`TranslationPanelWindow.xaml(.cs)`、`QuickSearchWindow.xaml(.cs)`、`Sections/TranslateSection.xaml(.cs)`、`Themes/Controls.xaml`、`ThemeService.cs`。

这是验证优先任务：先建立可复现用例，只有失败才改代码。旧截图不是当前视觉缺陷证据。本轮不要求换配色、圆角、图标或重做整个界面。

必须覆盖：Microsoft Pinyin 组词时 Esc 只取消组词；菜单打开时 Esc 先关菜单；请求中 Esc 取消当前任务并保留部分结果；再次 Esc 隐藏浮窗；译文与要点同时运行时取消对象明确；复制/朗读作用于当前阅读结果，部分结果遵循现有门禁；纯键盘可完成翻译、切换阅读、复制和关闭；焦点可见且没有循环陷阱。

视觉矩阵：浅/深/系统高对比，100/125/150/200% 缩放，最小支持窗宽，长模型名，错误态，混合 DPI 跨屏。用分组覆盖控制组合数量，关键浮窗跨屏需真实显示器验证。读屏要能读出图标按钮用途、阅读选中态和状态变化；流式字符不要逐字刷屏播报。

特别说明：当前浮窗 `OnPreviewKeyDown` 已有 IME 保护，旧规格“仅 Enter 接线”的说法过期，禁止以此为由再写一套保护。真机行为仍未验证。交付失败截图/步骤和修复前后证据；环境不具备则写未验证。依赖 R01。

### R05 · P2 · 建立技术翻译质量放行集

入口：`PRODUCT_SPEC.md`、`crates/popglot-core/tests/prompt_contract.rs`、`crates/popglot-core/src/benchmark.rs`、`docs/TRANSLATION_BENCHMARK.md`。新增建议：`tests/fixtures/translation-quality/` 与对应质量报告，不把自然语言质量塞进耗时 benchmark。

建议放行规则：受保护 token 逐字符正确；否定、操作对象、版本限制、危险命令含义不得反转；重大事实增补为阻断；其余准确性/可读性分别打分。先建立基线再约定分数阈值，不能追认阈值来制造通过。

fixture 只证明协议与保护机制，不能证明模型翻译质量。真实模型评测需有明确服务授权和成本边界；本次交接不授权调用付费服务。未运行真实模型时提交语料和方法，质量结论为未验证。依赖 R01 稳定请求身份，报告记录模型与配置版本。

### R06 · P1 · 修正文档承诺与隐私披露

入口：`docs/help/index.md`、`docs/help/privacy-and-security.md`、`README.md`、`PRODUCT_SPEC.md`、`Services/ProfileManager.cs`、`Services/OutboundPolicy.cs`、`FreeTranslateService.cs`、`HistoryStore.cs`。

已确认差异：

- 帮助页写 `PopGlot/Profile/{ProfileId}`；当前默认及生成路径为 `PopGlot/provider/{id}`，同时可能兼容历史目标。文档应区分当前格式和迁移兼容，不指导用户盲删凭据。
- 帮助索引写“硬件级加密托管”，本轮没有验证硬件依赖依据；改为精确描述“由 Windows 凭据管理器保存”。
- `HistoryStore.CanPersist` 使用有限正则检测特定敏感形状；文案不得暗示识别一切秘密。说明检测覆盖常见形式，敏感内容建议关闭历史，不能承诺完备识别。
- `OutboundPolicy.FreeEngineDestination` 仅列 Google 的一个域名，`FreeTranslateService` 还包含 `clients5.google.com`；统一所有用户可见披露与真实接收域清单。
- “撤销即立即中止所有请求”需核对在途请求取消链。发送边界拒绝后续请求不等于撤回已经发出的内容；按真实能力改文案，缺取消链再单独立任务。

验收：对照所有实际发送点、凭据目标和历史过滤实现逐句核对；文档检查不读取用户真实密钥；假 sender 测撤权后的新发送为零；在途取消单独记录结果。任何发现的未授权外发升级为 P0 阻断。依赖无。

### R07 · P2 · 建立可安全分享的诊断流程

入口：`docs/help/troubleshooting.md`、`Services/EngineWording.cs`、现有错误类型与日志实现（先定位复用）。

先做错误映射表：授权未开、缺凭据、认证失败、限流、模型不存在、网络超时、OCR 无文本、用户取消、存储失败。每项写“发生什么 / 已保留什么 / 下一步操作”。取消不显示成服务故障，重试不默默换外部接收方。

可选诊断导出只能含应用版本、OS、时间、错误码、协议、脱敏路由身份与耗时；导出前用户预览。不得包含原文、译文、截图、完整 URL 查询、请求头、密钥、模板正文或原始异常全文。默认零网络。先交付字段白名单与排障文档，再实现导出按钮。

验收：用带诱饵秘密的异常和 URL 检查导出；未知字段默认排除；写盘失败有反馈；相同错误在各入口含义一致。依赖 R06。

### R08 · P2 · 明确用户数据的迁移和恢复

入口：`Sections/DataSection.xaml(.cs)`、`HistoryStore.cs`、`Services/VocabularyStore.cs`、`Services/ProfileManager.cs`、`crates/popglot-core/src/prompt_store.rs`。

先盘点当前单项导出能力，交付迁移清单：历史、生词、模板、非秘密配置、凭据各如何处理。产品建议是提供显式备份/恢复入口，不是自动上传或自动收集数据。

实现前写出备份 schema 和范围选择；默认不导出凭据，不扩大历史保留策略。恢复必须先验证版本、大小、路径与内容，展示差异，备份原数据后再提交；遇到损坏、未知高版本、磁盘满或占用不得半覆盖。新增依赖默认不需要；选归档库须说明必要性与版本。

### R10 · P1 · 建立当前事实与证据台账

入口：`PRODUCT_SPEC.md`、`docs/overnight-polish-2026-09-23.md`、`docs/VERSIONING.md`、`scripts/verify.ps1`、`.github/workflows/ci.yml`、`.github/workflows/release.yml`。

现状：README 为 0.1.10；CHANGELOG 有未发布修复；规格仍存在“0.1.6 候选未发布”和旧 IME 缺陷描述。历史执行报告包括过期“未合并/未发版”与后续更正，容易被 AI 当作当前指令。

新增一份当前状态索引，明确哪些文档是历史快照，哪些条目被新证据替代。保留历史，不抹掉原始失败记录。台账每项记录提交 SHA、包哈希、dirty diff、测试环境、命令/步骤、预期、实测、结论、证据路径；不得在正文固定旧测试数为通过条件。

验收分层：E1 纯逻辑/Rust；E2 WPF 隔离/渲染；E3 真机桌面；E4 真实 Provider；E5 实际发布包/升级。低层通过不能替代高层。当前源码与已发包必须分列。

依赖无，应先做。仅写文档不需要运行全量构建；实现代码后按改动运行有意义的测试，最终执行现有 verify 门禁。WPF 测试前检查活动实例隔离约束，不结束用户进程。
