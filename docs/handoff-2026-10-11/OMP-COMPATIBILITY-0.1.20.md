# OMP 可用性与版本：0.1.20

原截图的「当前版本未放行」是当时 PopGlot 尚未启用该适配器的静态提示，没有证明 OMP 的安装版本不兼容。0.1.19 虽已实现 OMP 登录，其代码仍有两处不必要的严格版本限制：CliLauncher 要求 --version 等于 18.2.11；ProviderProfile.ExecutionFacts 要求保存的 ExpectedVersion 等于此常量。

0.1.20 对 OMP 移除这两处限制。ExpectedVersion 保留作为实际检测版本的诊断字段，未知格式或版本查询超时记录 unknown，不阻断真正的 RPC 检查。用户取消仍会取消操作。已有配置不需迁移、重新登录或手改版本号。Codex 独立策略未改。

可用性判定仍要求启用连接、完整程序入口/提供方/模型、运行及联网策略允许。实际启动后通过 get_state 验证 dumpTools 为数组且为空；模型目录必须是可解析数组；切换模型后再验证隔离。不存在版本号自动放行：协议字段缺失、工具启用、请求失败、非终态与取消仍拒绝成功，也不回退到其他引擎。

回归覆盖：模拟 18.2.12、20.0.0-beta.1 和无语义版本号的 OMP 在相同 RPC 协议下正常翻译；保存的旧版本不再禁用路线；缺少工具状态的 RPC 在发送原文前拒绝；已有登录/取消/终态/离线/WPF 检查继续执行。这些模拟版本不能当作对相应真实发行版的认证。本机已安装工具实际报告 omp/18.2.11。

Google 真人首次授权仍未验证。本机先前智谱测试的 429 是请求失败证据，与严格版本门禁是不同问题，不能通过放宽版本判断修复额度或限流。

验证记录：本地 Rust/fmt/clippy、47 项 PureTests、318 项 LogicTests 通过；最终 CLI/WPF 与真实本机只读探测 23 通过、0 失败。本机探测保留 stale-saved-version，仍成功读取实际版本 18.2.11、77 个提供方、42 个模型，推理提交数为 0。日志：`artifacts/cli-repair/v20-verify.log`、`v20-cli-probe.log`。未知版本、版本查询报错、3 秒查询超时均有模拟回归覆盖。
